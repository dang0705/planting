# 浇水水量档位重构（Q2-B）设计

日期：2026-07-01
状态：待实现
关联：`docs/code-logics/12_浇水提醒算法_逐步逻辑_盆型与Gate.md`（算法现状审计）

## 1. 背景与问题

浇水提醒里"建议水量"无论用户怎么操作永远显示 `normal`。审计（Q1）定位到这是**输入侧与输出侧双重断裂**，外加两个算法缺陷：

1. **输入硬编码**：`src/utils/care-behavior-timeline/sidecar.js:268` 把每个浇水事件的 `amount` 硬编码为默认值 `normal`（`CARE_BEHAVIOR_WATERING_DEFAULT_AMOUNT`），用户无法为每个日期选水量。
2. **DoseSelector 是摆设**：`DoseSelector.vue` 的 5 档滑杆绑定 `selectedDoseClass`，但该值从未传给后端。
3. **输出不回读用户剂量**：`hydration-load.js` 的 `computeAmountSuggestion` 只按 gate 三态输出 normal/thorough/unknown，无盆型时恒定 `normal + [50,200]`；`mist`/`small` 两档是死代码。
4. **基质多选失效（缺陷1）**：盆型档案 `substrate_type` 存的是 JSON 数组字符串（`[{material,ratio}]` 多选+比例），但后端 `normalizeSubstrateType` 只认单值枚举，JSON 数组会被归一为 `unknown`（保水因子 1.0）。用户精心多选的基质在算法里等于没选。
5. **基质因子表不全（缺陷1衍生）**：前端 9 种基质里 `ceramsite`/`perlite`/`coarse_sand` 后端因子表没有，落 unknown(1.0)。
6. **排水孔 DRY 判定失效（缺陷2）**：`hydration-load.js:358` 的 `isTooLongAgo = A || B || 5`，`|| 5` 恒真，使该阈值子句失去意义。

## 2. 目标（产品预期，已与用户对齐）

- **C**：既让用户历史剂量真实参与计算，又让输出档位更细。
- **方案 3 双轨**：算法建议档位（独立于用户习惯）+ 用户历史剂量回显对照，前端并排展示"建议 X / 你通常 Y"。
- **B 边界**：逐日水量能力做进共享 `CareBehaviorTimeline`，诊断流也获得；但诊断流默认行为等价现状。
- **A UI**：日历网格保留，网格下方新增"逐日期水量列表"（date + 5档 slider），删除全局 DoseSelector。
- 完整让盆型（体积 + 基质多选 + 排水孔）真实参与算法。

## 3. 非目标（YAGNI）

- 不做后端自取天气（Q3 单列）。
- 不改盆型档案的存储结构（`substrate_type` 仍存 JSON 数组字符串）。
- 不引入"用户习惯直接决定建议档位"的融合逻辑（那是方案 2，已否决——避免强化坏习惯）。
- 不动诊断流水分时间线的现有 payload 语义。

## 5. 详细设计

### 5.1 前端：CareBehaviorTimeline 逐日水量列表（改动 1）

- 新增子组件 `src/components/care-behavior-timeline/CareBehaviorWateringDoseList.vue`：
  - 数据源：timeline 已选中的浇水日期。
  - 每已选日期一行：`日期标签 + 5档水量 slider`（复用 DoseSelector 的 5 档视觉：不知道/喷雾/少量/普通/浇透）。
  - 选中新日期→新增行（默认 `normal`）；取消→移除；调 slider→更新该日期事件 amount。
- `CareBehaviorTimeline.vue` 新增 prop `enableDosePerDate`（默认 `false`）。仅为 `true` 时渲染列表。诊断流不传→行为等价现状。
- composable `useCareBehaviorTimeline.js` 扩展：维护"日期→amount"映射，change 事件 payload 的 `watering_events_10d` 每条带真实 amount（未选 slider 时 fallback `normal`）。

### 5.2 前端：删除 DoseSelector（改动 2）

- 删 `src/pages/index/components/DoseSelector.vue`。
- `WateringReminderSheet.vue` 移除 `selectedDoseClass`、DoseSelector 引用；日期选择弹窗内改传 `enable-dose-per-date` 给 CareBehaviorTimeline；"取消/确认"按钮从 DoseSelector 移到弹窗容器。

### 5.3 前端：amount 数据链根源修复（改动 3）

- `sidecar.js:268` 硬编码值保留为**未选时 fallback**；逐日列表选择的 amount 可覆盖。
- 确认 `watering_events_10d` 每条 payload 带真实 amount 一路传到 `fetchPlanner` 的 body（现有链路 `onTimelineChange` → `selectedWateringEvents` → `selectedWateringEventsForPlanner` 已透传，无需改结构）。

### 5.4 后端：基质多选加权解析（改动 4，缺陷1修复）—— pot-geometry.js

- 补全 `SUBSTRATE_RETENTION_FACTOR`（园艺常识，排水材料保水低）：
  - 新增 `perlite: 0.4`、`ceramsite: 0.5`、`coarse_sand: 0.4`（与 gritty 0.5、bark 0.7 梯度一致）。
  - 同步补进 `SUBSTRATE_TYPE` 枚举。
- 新增 `resolveSubstrateRetentionFactor(substrateType)`：
  - 单值字符串 → 查表（现状）。
  - JSON 数组字符串 `[{material,ratio}]` → 解析后按 ratio 加权平均各 material 保水因子（ratio 为百分数）；未知 material 按 1.0；权重和为 0 或解析失败 → 1.0。
  - 空/unknown → 1.0。
- `computePotGeometry` 里 `substrateRetentionFactor` 改用此函数。

### 5.5 后端：排水孔 DRY 判定修复（改动 5，缺陷2）—— hydration-load.js:358

- `isTooLongAgo = lastEffectiveRootWateredDaysAgo === null || lastEffectiveRootWateredDaysAgo >= Number(baselineIntervalDays[0]) || 5`
- 改为：`lastEffectiveRootWateredDaysAgo === null || lastEffectiveRootWateredDaysAgo >= (Number(baselineIntervalDays[0]) || 5)`
- 去掉恒真 `|| 5`，让 baseline min 阈值真正生效。

### 5.6 后端：amountClass 输出重构（改动 6）—— computeAmountSuggestion

启用 mist/small，按盆型体积对 gate 三态做档位细分。分档基于"单次建议水量绝对值（ml）"落桶：

体积→单次建议量（gate 已定倍率：DRY 20~30%，BASELINE 10~15%，WET 暂停）。在此基础上按**建议量上限 ml** 落档：

| 建议量上限 ml | 档位 |
| --- | --- |
| 0（WET） | unknown（暂停） |
| ≤ 30 | mist |
| 31 ~ 80 | small |
| 81 ~ 300 | normal |
| > 300 | thorough |

- 有盆型：先按 gate 算 amountRangeMl（沿用现有倍率），再按上限 ml 落档。小盆浇透可能落 small/mist（合理：小盆绝对水量本就少），大盆 baseline 也可能 normal/thorough。
- 无盆型（volumeMl≤0）：不再死板 `normal+[50,200]`。按 gate 给分级默认区间 + 对应档位：WET→unknown[0,0]；DRY→normal[100,200]；BASELINE→normal[50,150]。confidence 仍 `low`（无体积无法可靠落 thorough/mist，保守给 normal）。
- `stopCondition` 文案随档位微调（喷雾/少量/浇透）。

> 注：档位现在反映"下次建议的绝对水量规模"，语义比旧版（纯 gate 三态映射）更贴近用户直觉，且 mist/small 不再是死代码。

### 5.7 后端：双轨输出 userDoseEcho（改动 7）

- `buildWateringPlanner` 返回新增 `userDoseEcho`：从 `behaviorTimeline` 的 wateringEvents 提取用户近期代表性剂量。规则：取**最近一次非喷雾**浇水事件的 doseClass；若只有喷雾则取 mist；无事件 → null。
- `plant-user-http/app.js` watering-planner 响应 data 显式补 `userDoseEcho`（当前响应手动挑字段，需加）。
- `WateringReminderSheet.vue` 的 `plannerSummaryRows` 新增一行"你通常浇 {label}"（userDoseEcho 为 null 时不显示该行）。

### 5.8 诊断流兼容（改动 8，B 边界硬约束）

- `buildWateringPlanner` 被 `diagnose-http/utils/environment-context-v7.js` 调用（:1120）。
- `userDoseEcho` 是**追加字段**，不改现有字段语义 → 诊断流不消费即无影响。
- 基质加权、排水孔修复、amountClass 细分对诊断流是算法精度提升，返回结构不变（amountClass 仍是同名字段，取值范围扩大到含 mist/small）。
- CareBehaviorTimeline 的 `enableDosePerDate` 默认 false，诊断流两处使用（DiagnosePopup、question-package）不传→交互与 payload 等价现状。
- **回归验证**：诊断环境上下文构建无异常；诊断问诊水分时间线交互不变。
