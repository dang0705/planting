# 00｜文档总索引与阅读顺序

更新时间：2026-06-06

## 0. 最高准则

`code-base` 是诊断系统的最高事实源。本文档只描述当前代码已经实际运行或被代码显式表达的逻辑。

这次同步重点修正问诊部分的过时概念：追问、停止、输出资格已经不能再按旧文档的 ranking / score-gap / 多候选逐题协议理解。当前诊断仍由 route 模式汇总证据和决定输出；问诊题目按 mode question package 组织，固定题包必须回到 `getQuestionPackageByMode(mode)`、package queue、stop state 和 output eligibility。

## 1. 最短阅读路径

1. `02_诊断HTTP接口_请求响应与路由.md`：确认 `/diagnosis/start`、`/diagnosis/question/start`、`/diagnosis/answer` 的 handler 差异。
2. `03_诊断运行时主链路_逐步执行逻辑.md`：确认 route 主链、题包入口和 final 输出关系。
3. `05_问诊系统_问题生成_过滤_停止策略.md`：确认题包生成、queue 兼容层、停止与输出资格。
4. `06_问题排序_证据计分_输出守卫.md`：确认 route gate、候选 outcome 状态、可见输出守卫。
5. `07_结果格式化_公开响应_前端接入契约.md`：确认公开响应字段与前端题包处理。
6. `10_实施规则映射_开发约束_审计清单.md`：修改代码前后的审计清单。

## 2. 当前问诊模式一句话

当前诊断主链是 route 模式；当前问诊入口是 mode question package：代码先用 `getQuestionPackageByMode(mode)` 明确固定题包，再由前端整包展示/提交，后端用 package queue、持久化和 ownership 处理包内问题。非 package 路径仍按单题 queue-anchor 兼容。

## 3. 必须废弃或降级的旧概念

| 旧说法 | 当前代码事实 | 文档处理 |
|---|---|---|
| ranking / score gap 是问诊主判定 | route planner 和 route gate 是当前追问与输出主链 | 降级为历史概念，不作为执行依据 |
| 问诊可按旧 selector 任意多题推进 | 固定题包由 `getQuestionPackageByMode(mode)` 显式进入；非 package 路径保持单题 queue-anchor | 文档写成 package 与非 package 双路径 |
| 答满固定题数即可停止 | 停止依赖 `stage: final`、无 active queue、正式 outcome、正式 stop decision | 文档写成 stop/output 双闸 |
| `followUpRequired=false` 就一定能输出 | 还必须通过 stop state 与 output eligibility | 文档不得省略输出资格 |
| 黄叶模式只是普通单题追问 | 手动黄叶入口存在 4 题前置题包 | 文档必须记录题包响应和前端契约 |
| `questionQueue` 只锚定首题，所以黄叶 package 只能提交首题 | package queue 会保留包内全部问题；有效黄叶 package 会按同一当前轮次持久化/校验 sibling questions；非 package 路径仍按 queue-anchor 单题工作 | 文档必须明确 package 与非 package 的边界 |
| 旧 “最多两轮” 是事实 | `canOpenNextFollowUpRound()` 当前返回 true；配置另有 `maxRounds: 4`、`maxFollowUpRounds: 0` | 不再作为代码事实引用 |
