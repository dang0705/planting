# 10｜实施规则映射、开发约束与审计清单

更新时间：2026-06-06

## 1. 总规则

任何问诊、停止、输出资格相关改动，必须以当前代码为唯一事实源，并同步更新：

- `docs/code-logics/02_诊断HTTP接口_请求响应与路由.md`
- `docs/code-logics/03_诊断运行时主链路_逐步执行逻辑.md`
- `docs/code-logics/05_问诊系统_问题生成_过滤_停止策略.md`
- `docs/code-logics/06_问题排序_证据计分_输出守卫.md`
- `docs/code-logics/07_结果格式化_公开响应_前端接入契约.md`

- `ai_and_memories/.codex/memory.md`
- `ai_and_memories/.brv/context-tree/**`

## 2. 问诊改动审计清单

修改问诊前后必须检查：

- [ ] 是否仍明确当前唯一主问诊模式是 route 模式。
- [ ] 是否没有恢复旧 ranking / score-gap 作为追问或停止依据。
- [ ] 是否没有把旧 dynamic next-question helpers / active follow-up residues 写回当前事实。
- [ ] 固定题包是否通过 `getQuestionPackageByMode(mode)` 进入。
- [ ] 若引入题包，question queue 是否按 package 题数保留问题。
- [ ] 若引入题包，follow-up 持久化是否允许包内 sibling questions。
- [ ] 若引入题包，answer ownership 允许集合是否覆盖包内所有问题。
- [ ] 黄叶 4 题是否仍优先在 `static-question-package-start.js` 的模块级静态题包启动路径中产生。
- [ ] `yellowing_mode` 静态题包启动路径是否仍不加载 prior repository、manual fast path 或 `diagnosis-engine`，且默认路径仍通过 `persistRoundRuntime` 持久化。
- [ ] 黄叶题包是否仍带有 `outcomePolicy`。
- [ ] `questionPackage` 与 `uiHints` 是否仍能被前端 normalizer 保留。
- [ ] 前端是否按 package 模式整包展示和提交。
- [ ] `/diagnosis/answer` 是否能校验包内所有问题 key 与 option key。

## 3. 停止与输出资格审计清单

- [ ] 文档是否明确 stop state 才是停止事实。
- [ ] 文档是否明确 output eligibility 才是输出资格事实。
- [ ] 是否没有把“无 follow-up”简化成“一定可输出”。
- [ ] 是否没有把“答完 4 题”简化成“一定可输出”。
- [ ] route 无可见 outcome 时是否仍走保守 uncertain。
- [ ] uncertain 输出是否有合法理由。
- [ ] active queue 未清空时是否阻止输出。

## 4. HTTP 接口审计清单

- [ ] `/diagnosis/question/start` 是否仍直接 `buildFrontendResponse`。
- [ ] `/diagnosis/start` 与 `/diagnosis/answer` 是否仍经过 presenter。
- [ ] 文档是否保留这三个入口的差异。
- [ ] 前端是否没有假设三个入口响应路径完全一致。

## 5. 文档禁用表述

以下表述不得作为当前事实出现：

- “问诊由 ranking 分数差控制”。
- “score gap 达标即可停止”。
- “固定答满 N 题即可输出”。
- “questionQueue 是固定题包的题数权威”。
- “question-start 与 start/answer 的 presenter 行为一致”。
- “旧 Sxx all-in-one 是最新结构源”。

## 6. 允许保留的历史概念

旧 selector、旧 ranking、旧 Sxx 规则可以作为历史背景存在，但必须标记为：

- deprecated
- historical
- not current runtime source
- do not use for implementation

不得将它们放在 Facts 层。

## 7. Codex / AI 执行规则

AI 执行任务时：

1. 先看代码，后看文档。
2. 文档只用于加速定位，不作为反驳代码的证据。
3. 发现文档和代码冲突时，必须改文档。
4. 改 `new-rules` 后，才能改 `ai_and_memories` 的引用行号和章节。
5. 不能引用过时行号、过时章节或过时概念。
6. 对跨层不一致必须明说，不能为保持文档好看而隐藏。

## 8. 本轮已确认的高风险边界

黄叶 4 题题包当前是固定 package 协议事实：响应、前端展示/提交、package queue、持久化与归属校验都必须允许包内 4 题。高风险边界是不要把非 package 的单题 queue-anchor 语义外推到 package，也不要把 package 语义外推到所有诊断模式。
