## 2. 当前最大缺口

### 2.1 黄叶 package 后端包级闭环

当前代码已经支持黄叶 4 题 package 的响应与前端展示/提交，但后端 queue、follow-up 持久化和 answer ownership 仍首题锚定。若产品目标是整包提交稳定闭环，需要单独实现并补文档。

建议新增文档：`12_黄叶题包_后端队列持久化与归属校验.md`。

### 2.2 数据库 schema 未完整展开

仍需要独立整理：

- route groups / routes / gates / route questions。
- question option mappings。
- diagnosis sessions / follow ups / queue / runtime snapshot。
- stop state / output eligibility。
- review/detail 读取所需表。

### 2.3 行动建议体系还需要独立文档

当前 action advice、route outcome、uncertain 输出、retake guidance 与历史兼容字段分散在多个模块中。建议单独落地行动建议体系，避免具体问题、不确定方向和非问题状态的建议口径混乱。

### 2.4 前端结果页与 package 提交验收

前端源码已经存在于 `src/`，不再使用“缺少小程序前端源码”作为缺口。后续缺口应改为：前端 follow-up package 提交、结果页 route visible outcomes 与后端 answer ownership 的端到端验收文档不足。

## 4. 下一步建议

最优先补的是黄叶 package 后端包级闭环文档与实现。原因很直接：当前产品/前端已经出现 4 题 package 形态，但后端 queue 与归属校验仍按首题锚定。继续只改前端或只改文档会制造隐性提交失败。

第二优先是数据库 schema 与 route tables 文档，因为 route 模式已经是当前唯一主问诊模式，后续治理必须能解释 route group、gate、question 和 action profile 的关系。
