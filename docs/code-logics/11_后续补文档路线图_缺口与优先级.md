## 2. 当前最大缺口

### 2.1 黄叶 package 后端包级闭环

当前代码已经支持黄叶 4 题 package 的响应、前端展示/提交、后端 package 持久化和 answer ownership；session package state 仍可锚定首题作为当前/选择 artifact，但不能拒绝同一 package 当前轮次内的 sibling questions。后续缺口不再是“实现闭环”，而是继续补齐端到端验收与长期结构文档。

建议新增文档：`12_黄叶题包_后端队列持久化与归属校验.md`。

### 2.2 数据库 schema 未完整展开

仍需要独立整理：

- route groups / routes / conditions / route questions。
- question option mappings。
- diagnosis sessions / follow ups / package state / runtime snapshot。
- stop state / output eligibility。
- review/detail 读取所需表。

### 2.3 行动建议体系还需要独立文档

当前 action advice、route outcome、uncertain 输出、retake guidance 与历史当前字段分散在多个模块中。建议单独落地行动建议体系，避免具体问题、不确定方向和非问题状态的建议口径混乱。

### 2.4 前端结果页与 package 提交验收

前端源码已经存在于 `src/`，不再使用“缺少小程序前端源码”作为缺口。后续缺口应改为：前端 follow-up package 提交、结果页 route visible outcomes 与后端 answer ownership 的端到端验收文档不足。

## 4. 下一步建议

最优先补的是黄叶 package 后端包级闭环的端到端验收文档。原因很直接：当前产品/前端/后端已经支持 4 题 package 提交，但还需要把 package 与非 package 两条提交协议的 QA 证据固定下来。

第二优先是数据库 schema 与 route tables 文档，因为 route 模式已经是当前唯一主问诊模式，后续治理必须能解释 route group、condition、question 和 action profile 的关系。
