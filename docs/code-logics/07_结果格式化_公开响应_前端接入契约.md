# 07｜结果格式化、公开响应与前端接入契约

更新时间：2026-06-06

## 1. 公开响应原则

公开响应必须按 route 与 runtime artifacts 的结果呈现。前端不能自行根据题数、候选列表或旧 ranking 字段判断是否最终输出。

## 2. 前端响应构造

`buildFrontendDiagnosisResponse` 的关键规则：

- follow-up 状态读取 `publicResponse.followUpRequired`。
- 问题来源通过 `resolveResponseQuestions(publicResponse)` 获取，优先 `questions`，回退 `followUps`。
- 若构造出 `questionPackage`，保留 `questionPackage.questionCount` 个 follow-up。
- 若没有题包，则只保留 1 个 follow-up。
- 响应中透出 `questionPackage` 和 `uiHints`。

代码来源：`cloudfunctions/diagnose-http/app/frontend-response.js` 341-390；`cloudfunctions/diagnose-http/app/question-package-response.js` 3-67。

## 3. 黄叶题包响应契约

`questionPackage` 只有在以下条件同时满足时构造：

- `mode === yellow_leaf`
- `sourceMode === manual_yellowing_care_environment_frontloaded`
- 问题数正好是 4

构造出的题包包含：

- `mode`
- `sourceMode`
- `questionCount`
- `answerSubmitMode: package`
- `questionDisplayMode: package`

代码来源：`cloudfunctions/diagnose-http/app/question-package-response.js` 3-36。

## 4. 前端 normalizer

`diagnose-result-normalizer.js` 会：

- 读取 `rawQuestionPackage`。
- 用 `questionPackage.questionCount` 决定 `followUps` 归一化上限。
- 保留 `questionPackage`。
- 保留 `uiHints.maxQuestionsThisRound`、`questionDisplayMode`、`answerSubmitMode`。

代码来源：`src/utils/diagnose-result-normalizer.js` 100-111、216-218、261-267。

## 5. 前端 follow-up 页面

`follow-up.vue` 加载初始结果后，将 `result.value?.followUps || []` 传入问题流状态。

`question-flow.js` 会通过 `isPackageResult` 判断是否题包模式。在题包模式下：

- 用 `activeFollowUpQuestionIndex` 控制当前展示题。
- 最后一题前显示“下一题”，最后一题显示“完成问诊”。
- `canProceedFollowUpQuestion` 在 package 最后一题要求所有题已回答。
- `submitFollowUps` 在 package 模式下提交整个 `followUpQuestionStack`。
- 请求模式强制为 `answer_submit`。

代码来源：`src/pages/diagnose/follow-up.vue` 336-345；`src/pages/diagnose/follow-up/question-flow.js` 42-46、285-313、334-340。

## 6. 前端 payload

`buildFollowUpPayload` 会从 question stack 构造 `answers`，包含 question key、option key、option value 与 answer text 等。题包模式由页面层传入整包 stack，并指定 `requestMode: answer_submit`。

代码来源：`src/utils/diagnose-follow-up-payload.js` 10-80。

## 7. 必须暴露给前端的边界

前端可以按题包展示并提交 4 题；后端 answer endpoint 仍会做 question ownership 和 option mapping 校验。有效 `yellow_leaf` package 的包内问题会按同一当前轮次持久化为 allowed questions，legacy `questionQueue` 不得拒绝 package sibling questions。非题包路径仍按 queue-anchor 单题语义处理。

这不是前端文档可以忽略的细节；它是 package 与非 package 两条提交协议的边界。

## 8. 养护时间线环境上下文取数模式

- 前端在问诊场景请求 `weather-http/weather/environment-context` 时，带上 `mode: 'diagnosis'`，触发后端返回仅时光机历史窗口。
- `cloudfunctions/weather-http` 对 `mode='diagnosis'` 的 `environment-context` 请求，会对天气窗口进行裁剪，保留 `historicalDays`（兼容 `historical_days`）并将 `forecastDays/forecast_days` 计数归零，不再返回 `forecast` 与 `currentWeather` 字段。
- 构建时间线温湿度显示仍通过 `buildWeatherByDateFromEnvironmentWeatherWindow` 统一读取日期映射；诊断场景因此默认只使用历史窗口中的天气记录。

代码来源：`cloudfunctions/weather-http/app.js`、`src/api/weather.js`、`src/vue-query/weather/queries/environment-weather.js`、`src/pages/diagnose/follow-up/question-flow.js`、`src/components/DiagnosePopup.vue`。

## 9. final 结果读取


最终输出必须以 route visible outcome 与 result formatter / result read service 的公开口径为准。旧的 primary/secondary 字段只能作为兼容输入被重构，不是新的事实出口。

## 10. 前端不得做的事

- 不得根据 `followUps.length === 0` 自行判定最终诊断已可展示。
- 不得根据完成题数绕过后端 stop/output 资格。
- 不得把黄叶 package 当成所有模式默认题包协议。
- 不得忽略 `questionPackage` / `uiHints`，否则会把 4 题题包降级成 1 题。
- 不得把后端首题锚定风险隐藏成“接口稳定支持整包提交”。
