# 室内植物光照加减权算法设计

## 1. 结论

在微信小程序无法直接获得 Lux 的前提下，最简单、最易维护的光照算法不应追求“精确照度”，而应估算：

> 室内植物获得的等效日照小时数

也就是把属级养护数据中的：

```json
{
  "way": "全日照/半日照",
  "freq": [5, 8],
  "unit": "小时/天",
  "other": "以实际光照强度与直射时段校正，避免机械按距离判断"
}
```

转化为一个可计算目标：

```text
该属植物每天需要约 5–8 小时的有效光照。
```

然后用：

```text
历史天气 UV 指数
+ 历史天气日照/晴雨信息
+ 用户位置
+ 窗户朝向
+ 室内位置
+ 窗户/遮挡情况
```

估算当前环境是否低于、接近或超过该需求。

核心原则：

1. **UV 指数只做强度修正，不做主变量。**
2. **属级 freq 是最终判定基准。**
3. **朝向、窗型、位置、遮挡全部用配置表维护。**
4. **算法输出不要伪装成物理 Lux，而是输出“光照满足度”。**
5. **MVP 阶段只做加减权，不做复杂 DLI/PAR 模型。**

---

## 2. 推荐数据结构

### 2.1 属级光照模型

```ts
type GenusLightProfile = {
  way: '全日照' | '半日照' | '全日照/半日照' | '明亮散射光' | '耐阴';
  freq: [number, number]; // 小时/天
  unit: '小时/天';
  other?: string;
};
```

示例：

```json
{
  "way": "全日照/半日照",
  "freq": [5, 8],
  "unit": "小时/天",
  "other": "以实际光照强度与直射时段校正，避免机械按距离判断"
}
```

### 2.2 用户环境输入

```ts
type UserLightEnv = {
  facing: '南' | '东' | '西' | '北' | '阳台' | '无窗' | '不知道';
  windowType: '落地窗' | '标准窗' | '小窗' | '有窗帘' | '有遮挡' | '不知道';
  position: '窗边' | '房间中部' | '远离窗户' | '不知道';
  hasDirectSun: boolean | '不知道';
};
```

### 2.3 历史天气输入

```ts
type WeatherDay = {
  date: string;
  uvIndex?: number;
  sunshineHours?: number;
  daylightHours?: number;
  weatherText?: string; // 晴 / 多云 / 阴 / 雨 / 雪
};
```

## 3. 核心公式

### 3.1 计算户外基础有效日照小时

优先使用天气接口里的 `sunshineHours`。

如果没有该字段，用：

```text
户外基础日照小时 = 白昼时长 × 天气可用光比例
```

公式：

```text
baseOutdoorHours =
  hasSunshineHours
    ? mean(sunshineHours)
    : mean(daylightHours × weatherSunFactor)
```

天气系数：

| 天气 | weatherSunFactor |
|---|---:|
| 晴 | 0.60 |
| 多云 | 0.40 |
| 阴 | 0.25 |
| 小雨/阵雨 | 0.15 |
| 中到大雨 | 0.08 |
| 雪 | 0.10 |
| 未知 | 0.35 |

这里不要用 1.0，因为白昼时长不是等效直射时长。室内植物受益的是有效光照，不是“天亮了多久”。

---

### 3.2 UV 强度修正

UV 指数不能直接代表植物可用光，但可以代表太阳强度的大致变化。因此只做温和修正。

```text
uvFactor = clamp(
  1 + kUv × ((avgUv - uvRef) / uvRef),
  0.75,
  1.15
)
```

推荐默认值：

```ts
const uvRef = 8;
const kUv = 0.35;
```

解释：

- `avgUv = 8` 时，`uvFactor = 1`
- UV 高于 8，最多只加到 1.15
- UV 低于 8，最多只减到 0.75
- 避免 UV 把结果拉爆

---

### 3.3 户外等效日照小时

```text
outdoorEqHours = baseOutdoorHours × uvFactor
```

---

### 3.4 室内衰减因子

```text
indoorFactor =
  facingFactor
  × windowFactor
  × positionFactor
  × directSunFactor
```

#### 朝向系数

北半球默认：

| 朝向 | facingFactor |
|---|---:|
| 南 | 1.00 |
| 东 | 0.80 |
| 西 | 0.78 |
| 北 | 0.45 |
| 阳台 | 1.10 |
| 无窗 | 0.05 |
| 不知道 | 0.65 |

说明：

- 南向一般最强。
- 东向上午直射，较温和。
- 西向下午直射，强但热风险更高，所以略低于东向。
- 北向一般偏弱。
- 阳台可能比普通窗更强。
- 无窗基本不应判定为自然光满足。

#### 窗户系数

| 窗户类型 | windowFactor |
|---|---:|
| 落地窗 | 1.15 |
| 标准窗 | 1.00 |
| 小窗 | 0.80 |
| 有窗帘 | 0.78 |
| 有遮挡 | 0.75 |
| 不知道 | 0.90 |

#### 室内位置系数

| 位置 | positionFactor |
|---|---:|
| 窗边 | 1.00 |
| 房间中部 | 0.72 |
| 远离窗户 | 0.42 |
| 不知道 | 0.70 |

#### 直射系数

| 是否有直射 | directSunFactor |
|---|---:|
| 是 | 1.08 |
| 否 | 0.92 |
| 不知道 | 1.00 |

---

### 3.5 室内等效日照小时

```text
indoorEqHours = outdoorEqHours × indoorFactor
```

---

## 4. 与属级需求匹配

属级需求：

```ts
const [minNeed, maxNeed] = profile.freq;
```

例如：

```text
minNeed = 5
maxNeed = 8
```

### 4.1 不足程度

```text
lackRatio = (minNeed - indoorEqHours) / minNeed
```

如果 `indoorEqHours >= minNeed`，则不足为 0。

### 4.2 过强程度

```text
overRatio = (indoorEqHours - maxNeed) / maxNeed
```

如果 `indoorEqHours <= maxNeed`，则过强为 0。

---

## 5. 输出评分

推荐输出 0–100 分：

```text
durationScore =
  if indoorEqHours < minNeed:
    100 - lackRatio × 120
  else if indoorEqHours > maxNeed:
    100 - overRatio × overPenalty
  else:
    100
```

不同光照类型的过强惩罚不同：

| way | overPenalty |
|---|---:|
| 全日照 | 35 |
| 半日照 | 50 |
| 全日照/半日照 | 45 |
| 明亮散射光 | 65 |
| 耐阴 | 75 |

原因：

- 全日照植物更能承受偏强光。
- 耐阴植物更怕过强直射。
- 明亮散射光植物不能简单按“越亮越好”。

最终：

```text
score = clamp(round(durationScore), 0, 100)
```

---

## 6. 判定等级

| score | 等级 | 输出 |
|---:|---|---|
| 85–100 | 满足 | 当前光照基本满足 |
| 65–84 | 略不足/略偏强 | 可轻微调整 |
| 40–64 | 明显不足/明显偏强 | 建议调整位置 |
| 0–39 | 严重不足/严重偏强 | 建议立即处理 |

为了可行动，建议同时输出原因：

```ts
type LightOutcome = {
  score: number;
  level: '满足' | '略不足' | '明显不足' | '严重不足' | '略偏强' | '明显偏强' | '严重偏强';
  indoorEqHours: number;
  needRange: [number, number];
  reasons: string[];
  actions: string[];
};
```

## 7. 伪代码

```ts
function clamp(value: number, min: number, max: number) {
  return Math.max(min, Math.min(max, value));
}

function mean(values: number[]) {
  const valid = values.filter(v => Number.isFinite(v));
  if (!valid.length) return 0;
  return valid.reduce((sum, v) => sum + v, 0) / valid.length;
}

const WEATHER_SUN_FACTOR: Record<string, number> = {
  晴: 0.60,
  多云: 0.40,
  阴: 0.25,
  小雨: 0.15,
  阵雨: 0.15,
  中雨: 0.08,
  大雨: 0.08,
  雪: 0.10,
  未知: 0.35,
};

const FACING_FACTOR = {
  南: 1.00,
  东: 0.80,
  西: 0.78,
  北: 0.45,
  阳台: 1.10,
  无窗: 0.05,
  不知道: 0.65,
} as const;

const WINDOW_FACTOR = {
  落地窗: 1.15,
  标准窗: 1.00,
  小窗: 0.80,
  有窗帘: 0.78,
  有遮挡: 0.75,
  不知道: 0.90,
} as const;

const POSITION_FACTOR = {
  窗边: 1.00,
  房间中部: 0.72,
  远离窗户: 0.42,
  不知道: 0.70,
} as const;

function getDirectSunFactor(hasDirectSun: boolean | '不知道') {
  if (hasDirectSun === true) return 1.08;
  if (hasDirectSun === false) return 0.92;
  return 1.00;
}

function getOverPenalty(way: string) {
  if (way === '全日照') return 35;
  if (way === '半日照') return 50;
  if (way === '全日照/半日照') return 45;
  if (way === '明亮散射光') return 65;
  if (way === '耐阴') return 75;
  return 45;
}

function estimateBaseOutdoorHours(days: WeatherDay[]) {
  const sunshineHours = days
    .map(d => d.sunshineHours)
    .filter((v): v is number => Number.isFinite(v));

  if (sunshineHours.length >= Math.ceil(days.length * 0.5)) {
    return mean(sunshineHours);
  }

  const estimated = days.map(d => {
    const daylight = d.daylightHours ?? 12;
    const factor = WEATHER_SUN_FACTOR[d.weatherText ?? '未知'] ?? WEATHER_SUN_FACTOR.未知;
    return daylight * factor;
  });

  return mean(estimated);
}

function estimateLightScore(
  profile: GenusLightProfile,
  env: UserLightEnv,
  weatherDays: WeatherDay[]
): LightOutcome {
  const [minNeed, maxNeed] = profile.freq;

  const baseOutdoorHours = estimateBaseOutdoorHours(weatherDays);

  const avgUv = mean(
    weatherDays
      .map(d => d.uvIndex)
      .filter((v): v is number => Number.isFinite(v))
  );

  const uvRef = 8;
  const kUv = 0.35;

  const uvFactor = avgUv
    ? clamp(1 + kUv * ((avgUv - uvRef) / uvRef), 0.75, 1.15)
    : 1;

  const outdoorEqHours = baseOutdoorHours * uvFactor;

  const facingFactor = FACING_FACTOR[env.facing] ?? FACING_FACTOR.不知道;
  const windowFactor = WINDOW_FACTOR[env.windowType] ?? WINDOW_FACTOR.不知道;
  const positionFactor = POSITION_FACTOR[env.position] ?? POSITION_FACTOR.不知道;
  const directSunFactor = getDirectSunFactor(env.hasDirectSun);

  const indoorEqHours =
    outdoorEqHours *
    facingFactor *
    windowFactor *
    positionFactor *
    directSunFactor;

  const overPenalty = getOverPenalty(profile.way);

  let score = 100;
  let level: LightOutcome['level'] = '满足';

  if (indoorEqHours < minNeed) {
    const lackRatio = (minNeed - indoorEqHours) / minNeed;
    score = 100 - lackRatio * 120;

    if (score < 40) level = '严重不足';
    else if (score < 65) level = '明显不足';
    else level = '略不足';
  } else if (indoorEqHours > maxNeed) {
    const overRatio = (indoorEqHours - maxNeed) / maxNeed;
    score = 100 - overRatio * overPenalty;

    if (score < 40) level = '严重偏强';
    else if (score < 65) level = '明显偏强';
    else level = '略偏强';
  }

  score = clamp(Math.round(score), 0, 100);

  return {
    score,
    level,
    indoorEqHours: Number(indoorEqHours.toFixed(1)),
    needRange: [minNeed, maxNeed],
    reasons: buildReasons(profile, env, indoorEqHours),
    actions: buildActions(profile, env, indoorEqHours),
  };
}
```

## 8. 示例计算

### 示例 A：需求 5–8 小时，南向标准窗，窗边

输入：

```json
{
  "profile": {
    "way": "全日照/半日照",
    "freq": [5, 8],
    "unit": "小时/天"
  },
  "env": {
    "facing": "南",
    "windowType": "标准窗",
    "position": "窗边",
    "hasDirectSun": true
  },
  "weather": {
    "avgSunshineHours": 6,
    "avgUv": 7
  }
}
```

计算：

```text
uvFactor = 1 + 0.35 × ((7 - 8) / 8)
         ≈ 0.956

outdoorEqHours = 6 × 0.956
               ≈ 5.74

indoorFactor = 1.00 × 1.00 × 1.00 × 1.08
             = 1.08

indoorEqHours = 5.74 × 1.08
              ≈ 6.2 小时/天
```

结果：

```text
需求 5–8 小时，当前约 6.2 小时，判定为满足。
```

---

### 示例 B：需求 5–8 小时，北向小窗，房间中部

输入：

```json
{
  "env": {
    "facing": "北",
    "windowType": "小窗",
    "position": "房间中部",
    "hasDirectSun": false
  },
  "weather": {
    "avgSunshineHours": 5,
    "avgUv": 5
  }
}
```

计算：

```text
uvFactor = 1 + 0.35 × ((5 - 8) / 8)
         ≈ 0.869

outdoorEqHours = 5 × 0.869
               ≈ 4.35

indoorFactor = 0.45 × 0.80 × 0.72 × 0.92
             ≈ 0.238

indoorEqHours = 4.35 × 0.238
              ≈ 1.0 小时/天
```

结果：

```text
需求 5–8 小时，当前约 1.0 小时，严重不足。
```

建议：

```text
移到更靠近窗的位置；
优先选择南/东向窗；
如无法移动，建议补植物灯。
```

## 9. 推荐输出文案

### 9.1 满足

```text
当前光照基本满足该植物需求。

估算有效光照约 6.2 小时/天；
该属植物通常需要 5–8 小时/天。

建议保持当前位置，后续观察新叶大小、节间长度和叶色变化。
```

### 9.2 明显不足

```text
当前光照明显不足。

估算有效光照约 2.4 小时/天；
该属植物通常需要 5–8 小时/天。

主要原因可能是：
- 距离窗户较远；
- 当前朝向可用直射时段较少；
- 最近天气 UV 与晴天比例偏低。

建议：
- 优先移到窗边；
- 如果可以，改放到东向或南向窗附近；
- 若 7–10 天内新叶继续变小或徒长，建议补植物灯。
```

### 9.3 偏强

```text
当前光照可能偏强。

估算有效光照约 9.5 小时/天；
该属植物通常需要 5–8 小时/天。

如果叶片出现发白、焦斑、叶缘干枯，可以后退 0.5–1 米，或使用薄纱帘过滤中午直射。
```

## 10. 为什么不直接做 Lux

不建议在 MVP 阶段追求 Lux，原因有三点：

1. 微信小程序通常无法稳定读取环境光传感器。
2. 手机相机测光受机型、曝光、HDR、算法影响，误差难控。
3. 植物诊断更需要“长期有效光照水平”，不是某一刻的 Lux 数字。

更合理的 MVP 目标是：

```text
根据历史天气和室内位置，估算该植物是否长期处于光照不足/适中/偏强。
```

## 12. MVP 最小实现版本

如果要进一步压缩到最小实现，只保留这些字段即可：

### 用户只回答 3 个问题

```text
1. 窗户朝向：南 / 东 / 西 / 北 / 无窗 / 不知道
2. 植物位置：窗边 / 房间中部 / 远离窗户
3. 是否有明显遮挡：无 / 有窗帘 / 有楼栋或阳台遮挡
```

### 天气只取 2 个字段

```text
1. 最近 7 天平均 UV
2. 最近 7 天晴/多云/阴雨比例
```

### 输出只分 4 档

```text
满足
略不足
明显不足
严重不足
```

MVP 不建议过早输出“精确小时数”，可以显示为：

```text
估算有效光照：约 2–3 小时/天
该植物需求：约 5–8 小时/天
```

这比显示 `2.37 小时/天` 更可信。

## 13. 对青花植 route 模式的接入方式

这个算法不应变成 ranking，也不应回到复杂评分系统。它适合变成光照题包里的一个独立 outcome 生成器。

### 输入

```text
属级光照需求
+ 天气 UV
+ 用户朝向
+ 用户位置
+ 遮挡情况
```

### 输出

```text
光照不足 outcome
或
光照偏强 outcome
或
光照基本满足，不输出强干预 outcome
```

### 关键原则

```text
光照结果独立产出，不与浇水、施肥、通风做复杂因果组合。
```

如果植物照片出现强特异性光照症状，例如明显徒长、节间过长、新叶变小、叶片灼伤，则可以提高该 outcome 的特异性，但不要让它参与复杂 ranking。

## 14. 最终推荐

青花植 MVP 建议采用：

```text
属级 freq 需求
× 历史天气户外可用光
× UV 温和修正
× 朝向系数
× 窗户/遮挡系数
× 室内位置系数
= 室内等效光照小时
```

然后判断：

```text
低于 freq[0] → 光照不足
位于 freq 区间 → 光照基本满足
高于 freq[1] → 光照偏强
```

这是最简单、最稳定、最容易维护的方案。

不要追求 Lux。  
不要把 UV 当作植物光照本体。  
不要把它做成 ranking。  
先把它做成一个可解释的光照 outcome 生成器。
