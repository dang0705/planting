# P3 访问、知识和奖励闭环

首版主链：游客或已登录用户主动临时识别/问诊；浇水按已冻结的 `watering-decision-model/v1` 结构完成真实链路与参数验收后纳入 → 用户显式创建或绑定用户植物 → 同会话必要结果归属/认领；百度候选只能匹配已审核发布的规范身份。基础植物百科参考表 `tropicals_species_encyclopedia_ref` 已建立、逐步填充，完成来源、许可、身份映射与展示内容质量验收后可只读展示，不依赖 CMS 自动拓展；表中的展示养护与病虫害文本不得直接作为决策规则；结构化性状只能经 plant-knowledge 审核发布为 Internal Care Knowledge / Reference Profile 后供 Care 使用。会员/试用/免费 → CapabilitySnapshot → 必要 AI 额度。CMS 扩种、CMS 拓百科、贡献 AI 奖励及积分/等级/兑换保留在目标架构，首版不运行。Tropicals 实时 API 只保留为可选同步/来源核对/后续能力，不是百科详情或目录搜索的运行时主路径。


首版退出条件：真实 HTTP 认领与首版开放的会员/试用/AI 额度闭环；其中“微信登录 → 创建用户植物 → 读回”的验收必须在未预置能力快照的统一用户上完成，首次需鉴权的业务请求由 `subscription` 自动生成或刷新快照，试用仍从统一用户创建时刻起算，`identity` 登录接口不跨域写权益。基础百科若开放，必须先证明只读数据集的来源、许可、规范身份映射、质量和发布读回。CMS 扩种、拓百科与贡献奖励的失败/并发验收属于后续阶段，不作为首版退出条件。积分/等级/兑换后续任务仍须满足各自独立的验收条件。

首版运行范围按[首版运行边界](first-release-scope.md)执行：用户植物认领先于会员/试用/AI 额度深化；积分、等级、兑换与 CMS 贡献奖励的运行入口延后。已有账本实现继续接受必要回归测试，但其存在不等于首版开放，也不触发新的横向加固任务。

已登录用户主动临时使用并随后绑定用户植物，必须遵循[已登录临时案例合同](../contracts/authenticated-ephemeral-plant-case.md)：使用独立 UserPrincipal backing case，不得复用游客匿名 proof。016/017 DDL 设计已冻结；真实 MySQL 执行、HTTP 接线与 Expected 未验收前不得宣称该路径已运行完成。
