# 青花植 HTML / SVG 架构图布局规范（Layout Spec）

版本：v1.1  
适用范围：业务架构图、流程图、领域图、算法图、可折叠 HTML/SVG 架构图。  
目标：让布局与布线具备**可预测、可审计、可复用**的工程规则，避免“靠手工挪线修图”。

> 本规范不承诺任意复杂图都能自动得到审美最优解。它要求：在自动布局无法满足约束时，系统必须进入明确的降级策略（拆图、分区、增加画布、人工锁定通道），而不是继续生成重叠、穿节点、过度拐弯的错误图。

---

## 1. 核心不变量

### 1.1 语义优先于几何

布局不得改变业务语义：

- 条件门仍是条件门，不得为了布线方便变成普通节点。
- 依赖关系仍用虚线，不得与业务控制流混成同一种线。
- 折叠 / 展开不得改变 L0 对外主关系、方向和锚点语义。
- 同一条业务关系不得因为视觉优化被拆成两个看似独立的关系。

### 1.2 控制流与依赖流分层

- **实线**：业务主关系 / 控制流。
- **虚线**：知识、数据、外部能力依赖。
- 主流程拥有最高布线优先级；依赖流必须避让主流程。

### 1.3 同向线禁止共线重叠

- 两条水平线不得共享同一水平轨道区间。
- 两条垂直线不得共享同一垂直轨道区间。
- 不同方向的线允许正交交叉。
- 不允许为了“视觉合并”让两条不同语义的关系共用一段线。
- 如果业务确实存在汇聚，必须使用**显式汇聚节点**，不能靠线路黏连表达。

### 1.4 少拐弯优先于最短距离

候选路径优先级：

1. 直线（0 拐弯）
2. L 型（1 拐弯）
3. Z / U 型（2 拐弯）
4. 多段避障路径

只要 0/1 拐弯路径满足节点避障、端口容量、车道间距，就不得选择更多拐弯的路径。

### 1.5 空白通道优先于拥堵通道

路由器不能只看距离。空白区域应比“已有多条线的近路”更优先。

## 2. 分层布局职责

### L0 总架构

只表达：

- 核心业务主体
- 核心业务域
- 关键支撑域
- 关键条件分叉
- 核心跨域关系

不得展开算法、字段、题包、事件细节。

### L1 业务域 / 核心关系

解释 L0 中被折叠的节点或关键连线，不重复整个 L0。

### L2 子流程 / 领域模型

解释 L1 中仍然复杂的内部环节。

### L3 算法 / 规则

只解释计算模型和规则，不再承担跨域业务架构职责。

---

## 3. 节点布局规范

### 3.1 节点尺寸

普通矩形节点必须根据文字自动测量：

- `nodeWidth = clamp(textWidth + horizontalPadding * 2, minWidth, maxWidth)`
- 超过 `maxWidth` 时换行并增加高度。
- 不允许固定同一宽度导致长文本溢出或短文本产生大量空白。

推荐默认值：

- minWidth：140px
- maxWidth：300px
- 水平 padding：24px
- 垂直 padding：16px
- 行高：1.25 ~ 1.35

### 3.2 条件门

标准条件门必须：

- 使用菱形。
- **单一入线**。
- **多条带条件标签的出线**。
- 不承担 merge / 汇聚职责。

多条路径若需要汇合后判断：

`A/B/C → 显式汇聚节点 → 条件门`

而不是：

`A/B/C → 条件门`

### 3.3 节点间距

推荐：

- 同层水平节点净距 ≥ 64px
- 上下层垂直净距 ≥ 72px
- 路由主干附近额外留白 ≥ 32px
- 条件门与后续分支节点间距 ≥ 80px

当图线密度超过阈值时，优先扩大画布而不是压缩间距。

---

## 4. 端口（Port）规范

### 4.1 普通横向矩形节点

默认容量：

- 左短边：最多 1 根
- 右短边：最多 1 根
- 上长边：最多 3 根
- 下长边：最多 3 根

### 4.2 端口预约

所有边在路由前必须先预约端口：

1. 计算候选端口对。
2. 排除容量已满的端口。
3. 优先选择可形成 0/1 拐弯路径的端口对。
4. 同一长边多线均匀分散，不得贴在一起。
5. 端口确定后再进入路径规划。

### 4.3 长边端口位置

三槽建议：

- 25%
- 50%
- 75%

如果仅两根线：

- 33%
- 67%

不允许多条线从同一个几何点出发后再分叉。

---

## 5. 正交布线规范

### 5.1 路径形态

所有普通关系使用 Manhattan Routing：

- 只允许水平 / 垂直线段。
- 拐角使用统一圆角。
- 不使用斜线绕障。

推荐圆角半径：8~12px。

### 5.2 路由阶段

必须严格按以下顺序：

1. **完成所有节点布局**
2. 建立节点障碍矩形（含安全边距）
3. 预约端口
4. 建立可用水平 / 垂直通道
5. 先路由主流程
6. 再路由普通控制流
7. 最后路由依赖虚线
8. 放置标签
9. 全图碰撞审计

禁止“生成一个节点就立刻连一条线”。

### 5.3 路由 Cost Function

推荐：

```text
score =
  nodeIntersection * 100000
+ collinearOverlap * 50000
+ portCapacityViolation * 50000
+ insufficientLaneGap * 20000
+ unnecessaryBend * 500
+ bendCount * 120
+ congestedCorridor * 80
+ orthogonalCrossing * 8
+ pathLength * 1
```

含义：

- 穿节点、同向重叠、端口超限属于近似禁止项。
- 多一个不必要拐弯的成本远高于多走几十像素。
- 正交交叉允许，因此惩罚很低。
- 距离只作为最后优化项。

### 5.4 车道（Lane）

所有同向平行线必须占独立车道。

推荐：

- 最小线中心距：24px
- 高密度图：28~32px
- 线距节点边缘：≥ 20px
- 线距条件门：≥ 24px

同一通道已被占用时：

1. 尝试同方向相邻空车道。
2. 尝试另一侧节点端口。
3. 扩大局部通道。
4. 扩大画布。
5. 最后才增加额外拐弯。

---

## 6. 主干（Main Flow）与支线

### 6.1 主流程保护

主业务链必须尽可能：

- 垂直对齐或水平对齐。
- 0~1 拐弯。
- 不被依赖虚线穿插占用同向通道。

其他关系必须让路。

### 6.2 不隐式共享 Bus

如果多个节点都指向 Context Assembly：

- 默认使用多条独立平行线。
- 若确实需要 Bus，必须在图上创建显式 `Merge / Assembly` 节点。
- 不允许多条关系在半路黏成一根线。

---

## 7. 线路交叉、重叠与避障

### 允许

- 一条水平线与一条垂直线正交交叉。

### 禁止

- 同方向共线重叠。
- 线路穿过任何节点正文或边框。
- 箭头压在线段拐角上。
- 箭头与其他箭头黏连。
- 标签压在线、节点、箭头上。
- 同一节点多根线挤在同一个端口。

### 交叉优先级

当“多走一段距离”与“形成一次正交交叉”二选一时：

- 少拐弯优先。
- 一次清晰正交交叉通常优于 2~3 个额外拐弯。

---

## 8. 标签规范

- 条件标签必须靠近对应分支的**第一段独立线段**。
- 不得放在线路交叉点。
- 标签应具有背景描边 / halo，保证深色画布可读。
- 标签与线最小间距：6px。
- 线路过短无法放标签时，优先增加分支间距而不是覆盖节点。

---

## 9. 折叠 / 展开规范

### 9.1 L0 骨架不变

展开 L1/L2 时：

- L0 节点几何位置不变。
- L0 对外连线锚点不变。
- L0 对外连线走向不重算。
- 展开只是增加解释层。

### 9.2 原位展开

节点本身作为折叠面板标题头：

- 原节点位置就是展开锚点。
- 详情面板从节点原位向空间更充足的一侧展开。
- 面板不得把其他 L0 节点推走。

### 9.3 展开方向选择

依次评估：

1. 下方空闲面积
2. 上方空闲面积
3. 右侧空闲面积
4. 左侧空闲面积

选择可容纳详情面板且与 L0 主线冲突最少的方向。

---

## 10. 视口、溢出与滚动规范

这是 HTML 图最容易出错的部分之一。

### 10.1 滚动责任必须唯一

每个可视层级必须明确一个 Scroll Owner：

- L0 总图：`.graph-wrap`
- L1/L2 图：`.diagram-host`
- 原位展开面板：`.inline-body`

其他父容器不得无条件 `overflow:hidden` 截断 Scroll Owner。

### 10.2 不允许“内容被裁掉但没有滚动入口”

任何可能超出容器的图都必须满足至少一个：

- `overflow:auto`
- 自动扩容
- 缩放 / fit-to-view

不能同时：

- 固定宽高
- `overflow:hidden`
- 无缩放
- 无滚动

### 10.3 推荐 CSS

```css
.scroll-owner {
  overflow: auto;
  scrollbar-gutter: stable both-edges;
  overscroll-behavior: contain;
  -webkit-overflow-scrolling: touch;
}

.scroll-owner::-webkit-scrollbar {
  width: 12px;
  height: 12px;
}

.scroll-owner::-webkit-scrollbar-thumb {
  background: #315a79;
  border: 3px solid #171818;
  border-radius: 999px;
}
```

### 10.4 SVG 尺寸

- SVG 的 `viewBox` 必须覆盖全部节点、连线、标签和箭头。
- 不得依赖 `overflow:visible` 来“救”错误 viewBox。
- 容器可滚动时，SVG 应有明确 natural size / min-size。
- 大图宁可滚动，不得强制缩到文字不可读。

### 10.5 滚动条可发现性

macOS/Safari 的系统滚动条可能默认隐藏，因此 HTML 图必须至少提供一种可发现机制：

- 自定义 scrollbar 样式；或
- 容器边缘渐隐 / scroll hint；或
- “拖动画布 / Shift+滚轮”提示。


### 10.6 子图初始化尺寸：P0 Fit First

**P0 原则：子图首次打开时，先让弹框 / 展开面板根容器尽可能容纳子图自然尺寸；只有根容器已经达到当前可视区域上限后，才允许缩放子图；只有达到最低可读比例后仍无法完整容纳时，才启用 Overflow / Scroll。**

必须区分三层：

- **Layout**：节点坐标、节点尺寸、端口、Lane、线路径。
- **View Transform**：整张子图的等比视觉缩放。
- **Viewport**：弹框 / 展开面板根容器内，用户当前可见的画布区域。

初始化流程：

1. 读取子图 natural graph bounds。
2. 计算父级架构画布可提供给 popup 的最大宽高；当前屏幕不是 popup 的硬上限，超出当前屏幕时优先由外层总画布承担滚动。
3. **先扩展 popup 根容器**，目标是尽可能以 `scale = 1` 容纳子图及标题、说明、下钻入口等固定内容。
4. 若 natural graph + popup chrome 能完整放入父级架构画布允许范围：
   - popup 自动扩展至所需尺寸；
   - 子图保持 `scale = 1`；
   - 初始化不得产生 X / Y 滚动。
5. 若 popup 已达到父级架构画布可用上限仍放不下：
   - popup 保持在父级架构画布允许的最大合理尺寸；
   - 再计算 `fitScale`：

```text
fitScale = min(
  viewportWidth / graphWidth,
  viewportHeight / graphHeight,
  1
)
```

6. 若 `fitScale >= MIN_READABLE_SCALE`，使用 `fitScale` 完整显示子图，初始化仍不应出现滚动。
7. 若 `fitScale < MIN_READABLE_SCALE`，停止继续缩小，使用 `MIN_READABLE_SCALE` 渲染，并由 X / Y `overflow:auto` 承担剩余内容。
8. 等比适配只能改变 View Transform，禁止为适配容器重新排节点、重新路由或改变内部结构。

推荐优先级：

```text
Grow Popup To Natural Graph
→ Keep Scale = 1
→ Fit Inside Max Popup
→ Maintain Readability
→ Overflow / Scroll
```

推荐：

```text
MIN_READABLE_SCALE ≈ 0.72
```

这意味着：

> **“Fit First”不是把一张大图强行缩进一个小弹框，而是先让弹框主动适应子图；缩放与滚动都是后续降级策略。**

用户手动调整弹框根容器尺寸后：

- 不自动重新扩展 popup；
- 不自动重新 Fit；
- 保持用户调整前已经确定的子图视觉比例；
- 只改变 viewport；
- viewport 变小时自然产生 X / Y 滚动。

如果 L2 折叠内容在用户尚未手动 resize 时展开，根容器可以再次尝试在父级架构画布允许范围内自动增长；若超出当前屏幕，优先由外层总画布滚动。达到父级画布上限后再进入 Fit / Overflow 策略。

### 10.7 可调尺寸责任归属：优先由弹框根容器负责

当 L1 / L2 子图位于弹框、原位展开面板或其他复合容器中时，**四边 resize 的责任必须属于该弹框 / 展开面板的根容器**，不能把 resize 手柄挂在内部 `diagram-host` 或 SVG 画布上。

原因：

- 用户看到和操作的是“弹框 / 展开面板”的可视边界，而不是内部 SVG 的边界；
- 如果只改变内部画布 viewport，而外层根容器尺寸不变，会造成“看似可调，实际根容器不同步”的失效状态；
- 根容器才是布局、滚动、点击外部关闭、可见区域和交互命中范围的共同责任主体。

标准结构：

```text
Popup / Inline Panel Root   ← 四边 resize owner
├─ Header / Title
├─ Diagram Host             ← 子图 X/Y scroll owner
│   └─ SVG natural size     ← 不缩放、不重排
├─ Nested L2 sections
└─ Note / Footer
```

四边行为：

- 上边：调整弹框根容器的 top / height
- 下边：调整弹框根容器的 height
- 左边：调整弹框根容器的 left / width
- 右边：调整弹框根容器的 width

硬约束：

- resize 只改变**弹框 / 面板根容器的可视尺寸与位置**。
- 内部 `diagram-host` 自动适配根容器可用宽度，并保留自己的 X/Y `overflow:auto`。
- 内部 SVG `viewBox`、natural size、节点布局、线路路由、字体尺寸保持不变。
- 根容器缩小时，内部画布自然出现滚动；根容器放大时，内部画布可显示更多区域。
- resize 过程中不得重新执行 layout engine。
- resize 过程中不得把内部图强制 Fit-to-View。
- 根容器必须设置最小宽高，避免缩到无法阅读和操作。
- 根容器移动 / resize 后，点击外部关闭、遮罩命中和滚动责任必须同步到新的根容器几何范围。

推荐默认值：

```text
popup min-width   520px
popup min-height  320px
```

**例外：**如果某个图是独立页面中的唯一主体、没有外层弹框 / 面板，那么其顶层 viewport 自身可以成为 resize owner；但仍然禁止直接 resize SVG 本体。

### 10.8 resize 与 reflow 的边界

根容器 resize 与图重新布局必须完全分离：

```text
拖动弹框 / 面板根容器边缘
    ↓
改变根容器 width / height / 必要时 left / top
    ↓
内部 diagram-host 重新获得可用 viewport
    ↓
内部 SVG natural size 不变
    ↓
overflow / scrollbar 状态变化
```

禁止：

```text
拖动内部 diagram-host 边缘
    ↓
外层根容器尺寸不变
    ↓
形成“内层变了、外层没变”的假 resize
```

以及：

```text
拖动根容器边缘
    ↓
重新调用 layout engine
    ↓
节点移动 / 连线重算 / 图缩放
```

如果未来需要 Fit-to-View，应作为独立显式操作，不得偷偷绑定到 resize。

## 11. Hover / Focus 规范

线路必须有独立 hit-area：

- 实际线宽：1~1.5px
- invisible hit stroke：12~18px

Hover / Focus 时：

- 整根线高亮，不是局部段。
- 线宽提升到 3~4px。
- 箭头同步高亮。
- 条件标签同步高亮。
- 虚线保持虚线语义。

## 12. 自动布局审计（Preflight）

每次渲染完成后必须自动检查：

### Geometry

- [ ] 节点是否重叠
- [ ] 连线是否穿节点
- [ ] 箭头是否落在节点内部
- [ ] 标签是否碰节点 / 箭头

### Ports

- [ ] 短边是否 >1 根线
- [ ] 长边是否 >3 根线
- [ ] 多线端口间距是否足够

### Routing

- [ ] 是否存在同向共线重叠
- [ ] 平行车道中心距是否 ≥ 24px
- [ ] 是否有可用 0/1 拐弯路径却选择了 2+ 拐弯
- [ ] 是否无必要进入高密度区域
- [ ] 主流程是否被支线挤占

### Scroll / Viewport

- [ ] 图内容 bounds 是否全部落入 viewBox
- [ ] 容器是否存在 scroll owner
- [ ] 是否有 `overflow:hidden` 截断 scroll owner
- [ ] 横向超宽时是否可发现横向滚动
- [ ] 原位展开面板内容是否可完整滚动
- [ ] 子图 viewport 初始尺寸是否未超出父容器
- [ ] 子图 natural size 超出 viewport 时是否同时支持 X/Y 滚动
- [ ] 四边 resize owner 是否位于弹框 / 展开面板根容器，而不是内部 diagram-host
- [ ] resize 是否只改变根容器几何和可用 viewport，而没有触发 SVG 缩放、节点重排或重新路由
- [ ] 根容器四边 resize 是否可用且有最小尺寸保护

任何硬约束失败：**禁止交付**。

## 13. 自动路由降级策略

当自动路由找不到合规路径时，必须按顺序降级：

1. 换端口
2. 换空车道
3. 拉大节点间距
4. 扩大画布
5. 重新分层 / 分区
6. 拆为 L1/L2 子图
7. 人工锁定 routing corridor

不得通过：

- 同向重叠
- 穿节点
- 随机增加拐弯
- 强行压缩文字

来“完成”图。

## 16. 最终判定原则

一张合格图必须同时满足：

1. **语义正确**：图不会误导业务关系。
2. **结构清楚**：主流程一眼可读。
3. **线路独立**：同向不黏连，不靠线路重叠表示关系。
4. **空间合理**：有空白就优先使用空白，不钻拥堵区。
5. **拐弯克制**：没有必要的拐弯不得存在。
6. **可浏览**：大图可以滚动、缩放或拆层，绝不静默裁剪。
7. **可回放**：同一输入和布局约束应得到稳定结果。
8. **可审计**：所有违反规则的情况可以被自动检测。
