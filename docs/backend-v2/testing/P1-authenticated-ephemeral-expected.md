# P1 已登录临时植物：独立 Expected 草案

- 绑定任务：[P1 用户植物、身份和游客认领合同](https://app.clickup.com/t/z8v0kmr96y)。
- 真相源：根目录 Master Plan 第 61、64、86、1124、1929 行的已确认业务语义，以及[已登录临时案例合同](../contracts/authenticated-ephemeral-plant-case.md)。以下答案不从现行 `guest_plant_cases` DDL 或旧游客函数反推。
- 状态：**待转换成 TypeScript 可执行 RED**；尚未冻结临时案例有效期、表结构、路由及真实 CloudBase 身份接线，不得以本表宣称 P1 或 P3 已验收。

| 编号 | 场景 | 应当观察到的结果 | 证据档位 |
|---|---|---|---|
| `AE-01` | 已登录用户主动选择临时使用，随后识别或问诊 | 本次结果归属同一临时案例；不自动关联任一现有 `user_plant_id`，不写长期事实、状态、计划、提醒或时间线 | 业务硬锁 |
| `AE-02` | 同一用户、同一幂等键和相同创建参数重复提交 | 只创建一株案例并返回相同公开案例引用；换用新幂等键可另建一株案例 | 幂等合同硬锁 |
| `AE-03` | 同一幂等键但请求语义不同 | 返回冲突，不把第二次输入合并进第一株案例 | 幂等合同硬锁 |
| `AE-04` | 案例持有者明确选择绑定本人已有植物 | 一次性建立该案例到指定植物的归属；原识别/诊断/浇水记录的时间、证据、结论与建议不改写；不自动生成已执行养护事实 | 业务硬锁 |
| `AE-05` | 案例持有者明确选择创建新植物 | 新 `user_plant_id`、一次性成功绑定事实与公开结果在同一事务中成立；中途失败不得留下孤立植物或半绑定案例 | 事务与恢复硬锁 |
| `AE-06` | 当前用户提交其他用户创建的临时案例，或选择其他用户的目标植物 | 服务端拒绝，既不暴露案例内容，也不改变任何案例/植物/命令状态；不能凭公开案例引用证明所有权 | 归属与安全硬锁 |
| `AE-07` | 案例已过期、已绑定，或两个请求并发绑定不同目标 | 过期/已绑定案例不能第二次成功；并发最多一个目标成为事实。同键同参回读首次成功，同键异参或改目标冲突 | 一次性与并发硬锁；具体失效时长待冻结 |
| `AE-08` | 事务提交结果未知，调用方用原幂等键重试 | 先用新连接只读对账命令与成功事实；已提交则返回同一结果，未能确认则不创建第二株植物或第二条成功事实 | 故障恢复硬锁 |
| `AE-09` | 游客临时案例登录后认领，与已登录用户直接创建临时案例并列存在 | 游客路径仍必须验证匿名持有证明；已登录路径只验证创建时的同一统一 `user_id`，不能互借凭证或将游客案例伪称为登录案例 | 两类主体隔离硬锁 |

## 实施与验证层次

- `unit_fake`：案例归属判断、重复命令、非法目标和“建议不是事实”的领域边界；只替换仓储与时钟，不把替身回值当作 Expected。
- `unit_real_data`：在隔离真实 MySQL 中验证主体排他、案例一次性绑定、目标归属外键/约束、并发和提交未知对账；不能用静态 SQL 文本检查代替。
- `e2e_real_api`：经真实 HTTP 身份解析和 MySQL 读回验证登录用户可临时使用、跨用户拒绝、游客证明不串用及公开响应脱敏；本地假 Principal 不能证明 CloudBase 凭证有效。

实现前必须将每条适用的空值、边界、非法输入、幂等、失败回滚和并发风险分配到相应层，记录会使测试变红的具体错误改动。业务结果必须先有代表性可执行 RED，再改相关产品行为；合同草案本身不是 RED 证据。
