# P2 展示百科审核修订绑定：本地证据

## 独立预期与边界

- 预期来源：[CMS 展示百科补全 Worker](../implementation/cms-enrichment-worker.md)的“同一确定修订审核、改稿必须新修订重新审核”规则，以及 [P2 CMS 票据](../clickup/ticket-specs.md)的审核与不可变发布验收。
- 审核项若声明主题为 `encyclopedia`，其公开修订引用和内部修订键必须同时指向同一条不可变修订；缺失修订、错配引用、创建后整体改绑另一修订均必须由 MySQL 拒绝。原审核项保持原绑定。
- 测试层次为 `unit_real_data`：执行正式 001、002、012、013 顺序 DDL，使用隔离 MySQL 8.4 进行真实写入、拒绝和读回。未经过 CloudBase、CMS 管理员认证、发布事务、公开 HTTP 或贡献奖励。

| 场景 | 修改前 RED | 最终 GREEN |
|---|---|---|
| 内部键与公开引用错配，或百科审核缺少修订 | 旧 DDL 允许插入错配项，目标用例 1/4 失败 | 013 写入/更新门禁拒绝，目标文件 6/6 通过 |
| 旧审核项整体改绑到新修订 | 首版 013 只核对新目标，允许同时改动两列；新增用例 1/6 失败 | 旧绑定不可变，目标文件 6/6 通过 |
| 反事实突变 | 临时关闭 013 的旧绑定不可变分支，改绑用例 1/1 RED | 恢复原分支后，目标文件 6/6 GREEN；013 SHA-256 仍为 `609fa20c7288d1c327e4cb40b5f4822a5fc4fa36f160cc407f96bf5ad8cb8cad` |

Break：错误实现把已审核的 `revision_1` 重新指向 `revision_2`，让旧审核凭据覆盖新内容。Expected：必须拒绝且 `review_1` 仍绑定 `revision_1`。Real path：正式 DDL → 真实 MySQL `INSERT/UPDATE cms_review_items` → 原行 `SELECT` 读回。Mutation：关闭旧绑定不可变分支后，改绑用例确实失败；已完整恢复并再次通过。
