## 分层与覆盖义务

- `unit_fake` / L1：先验证原因归约、证据不足/冲突、禁忌动作和版本兼容的纯领域规则；外部 CMS 与模型均替换为固定的**独立**输入制品，不把替身输出当 Expected。`DK-01` 至 `DK-07` 中与领域职责相符的案例应形成先于产品实现的 `*.spec.ts`。
- `unit_real_data` / L3：验证来源、Outcome、Action、映射和 release 的 MySQL 约束、原子发布/回滚及历史读回；用本地真实空库而非内存仓库。它不能证明 CloudBase CMS 或 HTTP 已接通。
- `e2e_real_api`：后续验证真实 HTTP 身份与用户植物归属、CMS 已审核发布读回、公开脱敏和历史结果回放；HTTP 200、mock 或本地 MySQL 绿灯不能替代。
- L1 风险维：空证据、冲突/边界、非法引用、重复请求、发布失败、并发切换须分别评估；单纯结果归约若不持有本地可变状态，则“来源不覆盖用户态”不适用。L3 还须覆盖缺字段、鉴权、错误语义和写中断无半成品。具体适用性、用例名、RED/GREEN 与反事实突变证据在落盘可执行测试时逐项记录。

待冻结项未解决前，不得把此草案变成精确百分比阈值、全植物固定浇水间隔、药剂操作或 CMS active 内容。
