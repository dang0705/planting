# P2 植物知识发布制品不可变：本地证据

## 独立预期与证明范围

- 预期来源：[P2 CMS 分类、百科和发布票据](../clickup/ticket-specs.md)要求不可变 release、版本固定和回退审计；[植物分类合同](../contracts/plant-taxonomy.md)要求已发布内容由不可变版本与活动指针读取。发布头和明细写入后不能原地更新或删除；更正须创建新发布，活动指针可独立切换。
- 测试层次：`unit_real_data`。测试执行 `001_identity.sql`、`002_plant_knowledge.sql` 和新增 `014_plant_knowledge_release_immutability.sql`，使用隔离 MySQL 8.4，直接 SQL 写入、拒绝和读回。该子集只为隔离不可变性，不冒充全量空库迁移或应用发布事务验收。
- 未覆盖 CMS 管理员鉴权、审核有效性、制品摘要生成、Repository/事务、指针乐观并发、审计和 outbox、CloudBase、真实 HTTP。分类 active release 继续保持 STOP。

## RED → GREEN

| 场景 | 旧 DDL 的 RED | 加载 014 后的 GREEN |
|---|---|---|
| 发布头不可改 | `artifact_ref` 原地更新成功，目标测试失败 | 更新被 MySQL 拒绝，原引用读回不变 |
| 发布明细不可改删 | `subject_ref` 原地更新成功，目标测试失败 | 更新和删除均被 MySQL 拒绝，原明细仍可读回 |
| 未被引用的发布头不可删 | 第二条无明细、无活动指针的 release 可被删除，目标测试失败 | MySQL 自身拒绝删除，证明不是外键偶然拦截 |
| 活动指针可独立维护 | 旧 DDL 下可更新 | 014 生效后 `version` 从 1 更新至 2，未将发布头不可变误施于指针 |

最终目标测试 3/3；完整本地 MySQL 测试 17 文件 / 64 项；非 MySQL Vitest 84 文件 / 477 项；TypeScript 类型检查、目标 oxlint/oxfmt、manifest 13 文件 SHA-256 和入口校验均通过。

## 风险维度与真实性

| 维度 | 本切片结果 |
|---|---|
| I1 正常协作 | 新发布和明细可以插入；活动指针版本可更新。 |
| I2 缺字段/空集合 | N/A：本测试只验证已落盘发布的数据库不可变性，字段准入由 DDL 和后续发布合同验证。 |
| I3 错误语义 | 改写发布内容、明细、删除无引用发布均由数据库拒绝。 |
| I4 鉴权 | N/A：无网络入口；CMS 审核权限仍未验收。 |
| I5 写中断 | 被拒绝的修改后原记录可读回；跨表发布事务的失败回滚尚未覆盖。 |

Break：旧发布引用指向被替换的制品，或旧明细被删除，历史诊断与植物知识不能按原版本回放。Expected：两表只追加且指针独立。Real path：正式 DDL → 真实 MySQL `UPDATE/DELETE` → 独立 `SELECT` 读回；未替换数据库边界。Mutation：去掉 014 迁移后，三个目标用例全部 RED；完整恢复后 3/3 GREEN。
