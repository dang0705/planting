# CloudBase 认证通道

## 唯一认证入口

凡 CloudBase 操作需要网页登录、续期或重新授权，只允许使用用户 Chrome 的 `default/main` 主 profile。禁止使用 Codex 应用内浏览器、临时或隔离 profile、新建浏览器 profile，也禁止子代理各自建立登录态。

浏览器界面显示的 profile 名称可能是用户自定义名称；是否为主 profile 必须由主代理通过已连接的 Chrome 会话和既有 CloudBase 控制台登录态预检，不得仅根据显示名称猜测。

## 执行边界

1. 主代理负责认证预检、登录阻断协调和认证结果登记。
2. 子代理只消费主代理确认后的只读环境事实或受控工具结果；遇到认证失效时报告 `BLOCKED_AUTH`，不得另起登录。
3. Chrome 控制接口选择 `chrome` 只能确认浏览器家族，不能证明当前绑定的具体 profile。需要复用登录态时，必须复用用户已经在 `default/main` 主 profile 中打开的目标站点标签页；禁止为了探测登录态主动新建窗口或标签页。找不到既有标签页、跳转登录页或无法确认会话归属时，报告 `BLOCKED_PROFILE_OR_AUTH`，不得继续尝试其他会话。
4. 不读取、复制或记录 Cookie、访问令牌、二维码、验证码、密钥等认证材料。
5. 认证成功不等于获得写入授权。DDL、部署、网关切换、数据迁移、删除和付费能力仍须分别满足计划门与用户授权。
6. 预检只记录环境 ID、账号登录态是否有效、目标页面/能力是否可访问和检查时间，不记录敏感凭证。
