# CMS 展示百科补全 Worker

## 任务边界

Worker 仍属于 `plant-knowledge`，不新建云函数。内部 Job API 只负责签名、租约和调度机械能力。

## 流程

```text
已发布规范身份
→ 缺口唯一键
→ 聚合需求
→ 排序与平台预算
→ Qwen 受限结构化草稿
→ AJV/禁区校验
→ CMS 草稿
→ 人工审核
→ 不可变 release
→ 发布读回
→ subscription 贡献奖励事件
```

Qwen 只能生成简介、外观、分布和约 3 个 Q&A；分类、毒性、安全、浇水、施肥、光照、通风、温湿度、病虫害和诊断字段必须拒绝。

## 草稿修订与审核的内容边界

- 每条 `plant_encyclopedia_revisions` 是一次确定内容的修订：写入后，关联植物身份、结构版本、展示内容、内容摘要、来源和贡献者均不可原地修改。修改文字必须创建新修订，重新进入人工审核。
- `cms_review_items.draft_revision_internal_id` 只能指向所审的那条确定修订；既有批准不得自动继承新修订。审核状态变化不等于发布，发布仍须独立校验当前修订、审核决定及内容摘要，并形成不可变发布制品。
- 展示百科审核项的 `subject_ref` 必须与 `draft_revision_internal_id` 所指修订的 `revision_ref` 完全一致；不能用另一修订的公开引用套用这条批准。审核项创建后，其主题、修订键、修订引用和审核项引用均不得改绑；新修订须创建新审核项。数据库写入与更新均须守住该绑定。
- 上述数据库约束只封住原地改稿与审核项改绑；它不证明 CMS 管理员身份、审核权、内容摘要算法、发布事务或线上读回已经完成。

`content_hash` 只覆盖已通过 `plant-encyclopedia-display/v1` 校验的完整展示正文，不包含修订公开引用、所属植物身份、审核状态或时间戳。计算前递归按字典序排序对象键，问答数组保持提交顺序，不裁剪或重排文本；将紧凑 JSON 编码为 UTF-8 后取 SHA-256 小写十六进制。审核与发布必须重新读取同一修订并核对该摘要；未知结构版本或结构未通过时不得计算可发布摘要。
