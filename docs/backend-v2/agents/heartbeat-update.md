# Agent 30 分钟进度更新合同

本合同不是提醒，而是 ticket 的执行门禁。**没有完成 ClickUp 启动回写和本地绑定，子代理不得把任务标记为已开始。**

## 启动门禁

主代理分派任务时必须向子代理注入以下不可缺少的绑定信息：

```text
ClickUp ticket ID
ClickUp ticket URL
计划角色名
当前运行时子代理名（必须来自当前子代理树）
唯一工作范围
输入 SHA
```

子代理开始读取代码前必须按顺序完成：

1. 将 ClickUp 状态从 `backlog` 改为 `codex running`；如果尚未正式启动但已经完成依赖和代理绑定，则先改为 `ready for codex`；
2. 写入第一条启动评论，包含 ticket ID、当前子代理名、开始时间和预计下一次心跳时间；
3. 将同一信息写入本地 `tracker/module-status.json`；
4. 任一步失败，立即返回 `CLICKUP_BLOCKED`，不得继续声称 ticket 已开始。

Phase-P-1 看板当前真实状态与本地中文状态的固定映射如下：

| ClickUp 状态 | 本地状态 | 允许继续工作 |
|---|---|---:|
| `backlog` | 未启动、未完成运行时代理绑定 | 否 |
| `ready for codex` | 已完成依赖核对和运行时代理绑定，等待执行 | 否 |
| `codex running` | 子代理正在执行 | 是 |
| `human required` | 需要用户或人工提供输入/决策 | 否 |
| `blocked` | 环境、权限、依赖或外部事实阻断 | 否，等待解除阻断 |
| `review needed` | 子代理产物已提交，等待主代理或人工验收 | 否，等待验收 |
| `done` | 已验收完成 | 否 |

## 心跳

每个 `codex running` ticket 的负责人必须每 30 分钟更新 ClickUp 和本地 tracker：

```text
完成内容 / 下一步 / 已验证 / 未验证 / 新增依赖 / 阻断原因 / 完成百分比 / 更新时间
```

启动、阻塞、依赖变化和完成时立即更新。连续两次无更新标记状态失联，连续三次无更新转为阻塞并由主代理重新分派。

代码完成但未测试最高 75%；测试完成但未主代理验收最高 99%；只有主代理验收后才是 100%。

进度不是自由估计，必须以可核对证据为依据；每次心跳至少包含：ClickUp 回写结果、完成内容、下一步、已验证、未验证、阻断原因、完成百分比和更新时间。ClickUp 不可写时，必须保留本地 `CLICKUP_BLOCKED`，不能把本地百分比伪装成 ClickUp 已同步。
