# 诊断结论与行动建议的知识来源合同

- 合同阶段：P1 增量待冻结；本文件规定目标边界，不代表题包、知识或 CMS release 已通过验收。
- 业务所有者：`diagnosis`；CMS 编辑与发布通道：`plant-knowledge` 提供的受控发布基础设施；养护事实与计划的写入仍归 `care`。
- 适用范围：首版黄叶、萎蔫固定题包及动态虫害题包；后续新增症状入口或园艺病虫害原因时沿用同一合同。

## 两条不能混淆的分类轴

| 分类轴 | 回答的问题 | 首版示例 | 禁止混用 |
|---|---|---|---|
| 症状入口 | 用户看到了什么、从哪个题包开始收集证据？ | 黄叶、萎蔫、疑似虫害 | 黄叶不等于缺水；萎蔫不等于根腐；“虫害”入口不等于确认某种虫 |
| 园艺原因 | 已有证据支持哪些可能原因，还是尚不能确定？ | 非生物性养护/环境问题；生物性害虫；病原相关病害；混合原因；待判定 | 不以题包名、模型标签或百度植物识别结果直接充当确诊原因 |

原因目录首版只冻结足以服务现有题包的稳定代码与父子关系，保留后续扩展。非生物性原因可按水分、光照、温湿度、通风、基质/排水、肥盐/养分等**已获内部证据支持**的方向组织；生物性原因应区分害虫/螨等与病原相关病害。具体虫种或病原不能仅凭相似图片确定。允许多个原因并存，也允许 `unknown`（证据不足）结果；不要求把每次诊断强行归入唯一病因。

这个分轴参考 [UC IPM 的植物问题诊断指南](https://ipm.ucanr.edu/agriculture/floriculture-and-ornamental-nurseries/diagnosing-plant-problems/) 对非生物性、生物性及混合原因的区分，以及 [UC IPM 室内植物问题指南](https://ipm.ucanr.edu/home-and-landscape/houseplant-problems/) 对先识别问题、再选择处置方式的要求。外部资料是审核证据，不是可直接复制或自动发布的 CMS 内容；发布前仍需核对具体植物适用性、来源版本、许可与本地使用条件。

## 来源、结论与行动三层

1. **来源证据与来源主张**：内部已接纳的植物身份、题包及答案、私有视觉证据、原子环境事实/快照、已确认养护事实，与经过编辑核验的园艺文献/机构资料。来源主档须记录机构/作者、标题、可追溯定位、核验时间、适用植物/场景、版权或使用边界与审核人；来源主张须记录“具体支持或反驳什么判断/行动”、在原资料中的定位及内部证据引用。Outcome、Action 及两者映射都分别引用经审核的来源主张，不能仅给整类动作机械挂一篇来源。来源失效或相互冲突时暂停对应条目发布或降级为“待判定”。百度识别只产生植物身份候选；Qwen 只能在受控边界内整理已接纳证据或起草待审核文本，二者都不是病因和处置的权威来源。
2. **Outcome（诊断结论条目）**：使用稳定 `outcomeCode`、中文名称、症状入口标签、园艺原因分类、适用植物范围、支持/反驳证据条件、不确定性表达、来源引用和不可变内容版本。一个症状可映射多个候选结论；一个原因可由不同症状进入。结论是对本次证据的有界判断，不把“可能”写成“确诊”。
3. **Action（行动建议条目）**：使用稳定 `actionCode`、中文目的与具体步骤、适用结论/条件、禁忌或停止条件、执行顺序、复查观察点与时间条件、风险级别、来源引用和不可变内容版本。允许安全的先观察/补拍/检查类通用行动；涉及药剂、毒性、食用、儿童/宠物或其他高风险处置时，若目标、适用场景和安全依据不足则不得发布或展示。行动不是已执行事实、计划或提醒。

Outcome 与 Action 是多对多的受审核映射：只有结论命中、证据条件满足且无禁忌时，才能把行动推荐给本次用户；证据不足时优先返回安全检查、补问或观察。一次结果必须记录所用题包、原因目录、Outcome、Action、映射规则及来源的 release 引用与哈希，历史结果按原版本回放，不因后续 CMS 修改而改写。

用户看到的是中文的“判断依据与资料来源”：可公开的机构/标题、更新时间和合法公开链接，以及本次证据为何支持或不能支持该结论；内部来源主张 ID、原文摘录、私有证据路径和未授权资料不得进入响应。若资料许可或有效性不足以公开链接，应展示已审核的来源类型与审阅说明，不伪造引用。公开字段、链接白名单和脱敏例子须在 P1 DTO 中冻结。

## CMS 扩展与发布门

```text
来源登记与许可/适用性核验
→ 编辑创建或修订原因、Outcome、Action、映射草稿
→ 结构校验 + 稳定代码/引用完整性 + 来源与安全审查
→ 领域审核（病虫害与高风险动作须人工复核）
→ 同一兼容发布包中生成不可变 release 和 SHA-256
→ 灰度/回读/回滚
→ diagnosis 请求锁定一个已发布的兼容版本快照
```

CloudBase CMS 只负责受控编辑与审核，不直接作为运行时热读真相源。`diagnosis` 拥有语义、结果归约、行动筛选与发布准入；`plant-knowledge` 可复用 CMS 基础设施，但**展示型植物百科自动补全 Worker 不得写入**园艺原因、Outcome、Action、诊断/治疗或安全知识。新增知识须有独立草稿、独立审核和独立 release；删除/撤回用新 release 与审计记录表达，不原地篡改已用版本。发布时校验题包引用、植物身份适用范围、原因父链、Outcome→Action 条件与来源均可解析；不兼容发布阻断，不静默落到模型自由生成。

v2 现有通用 `content_releases` 中的 `diagnosis_rule` 只提供潜在版本容器，现有 CMS 审核外键仍面向百科修订；它们**不证明**诊断来源主档、来源主张、Outcome/Action 映射和人工审核已经建好。P1 必须裁决是扩展受控发布基础设施还是为诊断域建专用发布结构，冻结单一写者、跨域只读合同与回滚事务；禁止 `diagnosis` 绕过 Repository 直接修改 `plant-knowledge` 所属表。

## 首版验收与阶段绑定

| 阶段 | 必须交付的最小证据 | 未通过时 |
|---|---|---|
| P-1/P1 | 审计旧黄叶/萎蔫题包、八类虫害候选、白粉病/煤污和行动文本；冻结双轴代码、来源主档/来源主张、Outcome/Action/映射 DTO、用户侧来源呈现边界与独立 Expected；标明保留/转换/重建 | 只阻断相关诊断知识发布与依赖它的问诊验收，不抹除已经通过的其他 P1 合同 |
| P2/P3 | CMS 草稿/人工审核/不可变发布/回滚的最小通道，校验来源、适用性、禁忌与跨引用；首版代表条目可读回 | 不以旧表、模型生成文本或未发布草稿充当线上知识 |
| P4 | 黄叶、萎蔫、虫害代表案例：同症状不同原因、同原因不同症状、混合/未知、证据冲突、禁忌动作、知识撤回及版本回放；输出具体、安全、可复查步骤 | 基础结果内容底线不通过，不能以“增强实验失败回退”宣称 MVP 诊断达标 |
| P5 | 真实 HTTP + MySQL + CMS 发布读回、权限/脱敏、错误/回滚与历史结果重放；模型生成只表达已发布知识 | 对应能力保持未验收 |

需要改变题包优先级、原因目录版本、Outcome/Action 发布指针或安全阈值时，先在业务关键变量目录登记 owner、来源、消费方、回退和阻断范围；P1 未冻结值不得由领域代码自行设默认值。首版只扩充现有症状入口所需的知识面，不建设无限制的病虫害百科或自动确诊系统。
