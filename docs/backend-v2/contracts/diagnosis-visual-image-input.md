# 视觉诊断图片输入合同

- 合同版本：`diagnosis-visual-image-input/v1`
- 状态：用户 2026-10-10 裁定；**合同已冻结、未实现**
- 所有者：`diagnosis`（模型输入侧）；协作：`storage`（上传资产策略）
- 机器事实源：[diagnosis-visual-image-input.v1.json](diagnosis-visual-image-input.v1.json)

## 规则

1. **每次诊断最多 3 张图**（配置目录 `diagnosis.visual.max_images`，已冻结，策略发布层，取值 3）。补拍作为新的一次调用，不在同一次调用里叠加图片。
2. **客户端不限制像素**：端上可以上传原图，只受上传资产策略约束（`storage.upload.max_image_bytes`，当前 5 MB；`storage.upload.allowed_mime_types`：JPEG / PNG / WebP）。
3. **服务端缩放是必经步骤**：图片送入模型前，必须统一缩放到 **1024² 像素（1,048,576 像素）以内**；保持长宽比，**只缩不放大**。这是模型输入侧的代码层硬上限，任何配置、客户端参数或请求都不能去掉或调高。不设上限时，单图最多可达 2,562 tokens（默认像素上限）。
4. **输入 token 预算**：固定前缀（预留 8,300）+ 上下文摘要 ≤600 + 用户文本 ≤300 + 图片数 × ≤1,026，必须 ≤ 32,000 × 90% = 28,800 tokens。3 张图时约 12,200 tokens。适配器调用前按此估算，超出时拒绝并返回可解释的错误，不静默截断图片或上下文。

## 实现方式（优先使用模型侧官方能力）

- **首选：百炼的 `max_pixels` 参数。** 在每个图片内容块上写 `max_pixels: 1048576`，由百炼在模型侧缩放（官方图像理解文档：超过像素上限的图片会被缩小到上限以内，单图 token 上限 = max_pixels ÷ 32 ÷ 32；默认 `vl_high_resolution_images=false`，**不得开启高分辨率模式**，否则 `max_pixels` 会被忽略，单图最多 16,384 tokens）。2026-10-10 探针已实测：设为 1024² 时单图 882～1,016 tokens。
- 这样**服务端不需要自己做图像解码与重编码**，因此**不需要新增图像处理依赖**。传输限制也满足：URL 输入单图 ≤20 MB（Qwen3.5 及以上），而上传资产上限是 5 MB。
- 「服务端缩放」由适配器强制写入 `max_pixels` 来落实：参数由服务端代码写死，客户端和配置都不能覆盖；适配器测试必须断言每个图片块都带这个参数，且值不超过 1,048,576。
- **何时需要服务端自行缩放**：只有在需要换到不支持 `max_pixels` 的模型或供应商、需要减少传输体积，或者需要统一转换格式（例如 HEIC）时，才需要在服务端解码和重编码（JPEG/WebP）。这需要新增图像处理依赖（例如 `sharp`），按宪章必须先说明兼容性、版本、维护状态与替代方案，并经用户确认后才能安装。**当前不安装。**

## 不变量

- 图片只用 HTTPS 临时地址交给模型；产品运行时不接受 Base64（评测脚本的本地内联只用于离线评测）。
- 预算参数（前缀预留、上下文上限、图片上限）一旦变化，必须同步更新机器事实源，并重跑预算合同测试。
