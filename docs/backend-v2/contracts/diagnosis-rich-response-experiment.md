# 诊断内容增强的首版实验合同

- 合同版本：`diagnosis-rich-response-experiment/v1`
- 业务所有者：`diagnosis`；AI 额度结算所有者：`subscription`

## 目标与事实边界

首版黄叶、萎蔫和虫害诊断需要给用户充实、可执行的解释与行动建议。可以借鉴“结构化生成补足表达”的形式，诊断事实来自已接纳的图片证据、用户回答、植物身份、环境与内部已发布知识。**经用户 2026-10-10 裁决（修订 C1），视觉诊断生成式版本组（`diagnosis-visual-gen/*`）可由模型在固定前缀给定的病因分类体系与安全规则内，生成本次病因判断和处理方案**；模型仍不得另造植物身份、盆土状态、毒性或背景事实，病因必须先以闭集病因编号表达，处置不得超出安全用药规则。

Outcome 结论与 Action 行动的来源、园艺原因分类、禁忌和 CMS 发布关系以[诊断知识来源合同](diagnosis-knowledge-sources.md)为前置。题包路径的增强模型只可在本次已接纳证据和锁定的兼容发布包内组织说明，不得新增诊断原因、处置步骤或药剂主张；发布包缺失时不能用更长的生成文本掩盖基础知识空白。**视觉诊断生成式版本组例外（用户 2026-10-10 裁决，修订 C2）**：病因只能取自该版本固定前缀中的闭集病因编号；处置步骤可由模型按本次证据生成，但药剂只能取自[允许名单](diagnosis-visual-gen-agent-allowlist.v1.json)（待园艺来源审核），不得给出剂量，必须提示按产品标签使用，可食用或可食用性未知时必须提示安全间隔期；高风险步骤必须给出理由。**重复处理（用户 2026-10-10 裁定 D15）**：允许提示需要重复处理，但只能用「按产品标签的间隔重复处理，并在下次处理前复查」这类通用表述；禁止写具体天数或次数，例如禁止「每 7 天喷一次」「连续喷 3 次」「间隔 5～7 天复喷」「3 天后再喷」。这一限制只针对用药步骤，观察与复查类步骤可以写天数。上述约束由[公开结果 v2 Schema](schemas/diagnosis-result.v2.schema.json)与服务端安全门强制，任一不满足则整份拒绝。已审核知识发布包上线后，同一病因编号优先展示已审核内容。

现行 `qwen3.5-flash`、Prompt SHA-256 和 `diagnosis-model-output/v1` 已锁定。增强版必须作为新 Prompt/Schema/成本策略组合版本提出并独立验证；没有通过版本发布门时继续使用现行合同，不能覆盖原 release。

## 建议输出的表达范围

结构化结果至少区分：已有证据、诊断结论与不确定性、建议立即做的动作、明确暂不做的动作、用户可复查的观察点、何时再检查以及需要补充信息的原因。行动项需说明对应的已接纳证据和适用条件；当证据不足或存在冲突时，先建议安全检查或补问，不给确定病因或有风险的处置指令。建议进入用户植物仍是 Proposal，只有用户确认实际行为后才形成事实。

## 成本与会员额度的开放门

使用同一批覆盖黄叶、萎蔫、虫害、单图、多图、证据不足和冲突的测试样本，分别运行现行版本与增强候选版本。逐产品动作记录输入/输出 Token、图片计量、模型循环、缓存命中、人民币微元成本、预占点数、最终结算点数、失败/重试和响应时长；按 0 缓存命中另算保守预算。比较单动作分布及重度用户在 2,000 点订阅周期内的可用次数，并评估 9.9 元会员的供应商成本上界。

每个候选动作必须在现有业务关键变量目录中冻结 `maxInputTokens`、`maxOutputTokens`、`maxImages`、`maxModelLoops`、`maxCostMicros`、`estimatedPoints`、价格快照和 `costPolicyVersion`。新版本如果增加单动作预占或最终扣点，须先给出用户可理解的动作级用量说明，不能因内部多调用几轮就在同一用户动作上重复收费。超出预占的已发生成本由平台先承担并进入对账；余额不足必须在下一次模型调用前停止。未冻结供应商价目、真实样本成本和动作上限时，对应增强版保持关闭。

## 比较与放行

1. 由独立 Expected 检查建议是否比现行版更具体，同时无虚构事实、危险处置、证据越权或问诊状态污染；保留证据与版本可回放。
2. 以同一动作的成本、额度和时延分布与现行版对比，记录获益来自哪里、增加了多少模型调用和 Token；图片与模型内部循环都归到一个 `productActionId`。
3. 候选版只在已审核的模型、Prompt、Schema 和价目快照范围内灰度；监测质量、错误、成本与额度申诉。任何门槛失败立即回到最近已验证的版本，并保留失败审计。
4. 如果增强版无法在可接受的用户额度体验和已批准成本上限内交付，应缩短输出、减少重复上下文或降低调用次数后重测；不得通过静默提高用户扣点来掩盖成本。候选失败可回退已验证版本保障服务安全，但不能据此宣称“首版诊断内容与行动建议已足够充实”的产品目标验收；若多轮受控重测仍不成立，必须将质量、成本和用量取舍交由用户裁决。

此合同只设实验和验收边界，不声称已经完成真实模型成本测量，也不预设新的价格或点数。
