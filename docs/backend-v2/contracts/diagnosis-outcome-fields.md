# 诊断 Outcome 字段设计（P1 待冻结）

本文件为 [诊断知识来源合同](diagnosis-knowledge-sources.md) 的字段级展开，属于 P1 设计输入，不代表 DTO、DDL、CMS 模型或公开 API 已验收。参考样本是用户提供的“一隅植物志”结果页截图（2026-09-23）：它展示了问题类型、约 75% 置信度、主要证据、紧急程度、是否隔离、识别依据、立即处理、后续养护、预防、注意事项和其他可能。截图只能证明这些**页面信息分区**，不能证明一隅的真实数据库字段、接口 Schema 或准确率。

## 三种对象必须分开

| 对象 | 回答的问题 | 所有者 | 不得混入 |
|---|---|---|---|
| 已审核 Outcome 条目 | 在什么植物和证据条件下，可以作出哪种有界结论？ | `diagnosis` 知识发布 | 某个用户的照片、回答、模型自评百分比、具体执行动作 |
| 本次诊断结果 | 这株植物的本次证据支持或反驳什么，仍有哪些不确定性？ | `diagnosis` 运行结果；长期结果归属 `user_id + user_plant_id`，临时结果归属案例 | 未发布知识、未经确认的养护事实 |
| 已审核 Action 与结论—行动映射 | 在结论与禁忌条件满足时，用户应如何处理、复查与预防？ | `diagnosis` 知识发布；实际行为仍由 `care` 确认写入 | Outcome 条目中的自由文本操作清单 |

## 已审核 Outcome 条目字段

以下是**语义字段清单**，英文键是拟议的 TypeScript/JSON 标识符；P1 仍须冻结类型、必填性、长度、枚举、数据库映射与 CMS 编辑表单。没有可靠证据的值必须允许表达“未知/待判定”，不能靠默认值补齐。

| 字段 | 中文含义与约束 | 来源与校验 |
|---|---|---|
| `outcomeCode` | 稳定结论代码；改文案不换代码，改变判断语义须新版本或新代码 | 发布域唯一；历史结果可回放 |
| `displayNameZh` | 中文结论名称；不把“疑似 A/B/C”拼成伪确诊标题 | 人工审核；和原因、确定性匹配 |
| `summaryZh` | 面向用户的简短解释模板；只解释结论，不暗示已执行处理 | 人工审核；不得引入未获证据支持的事实 |
| `symptomModeCodes` | 可从哪些症状入口进入；黄叶、萎蔫、疑似虫害等是入口，不是病因 | 引用已发布题包/模式代码 |
| `causeCode` | 对应园艺原因代码；可为非生物性、害虫、病原、混合或待判定的具体节点 | 引用同一兼容发布包的原因目录 |
| `problemTypeCode` | 用户可理解的问题类型，如生理性养护损伤或疑似害虫；是 `causeCode` 的受审展示投影 | 不由模型自由造类；中文标签可版本化 |
| `applicablePlantScope` | 适用植物身份、属/科或更宽范围，及明确的不适用范围 | 与规范植物身份目录核对；身份未知时只用允许的通用条目 |
| `requiredEvidence` | 作出本结论必须出现的观察或回答；包括来源、部位、时间和最低可靠性要求 | 规则可执行；缺失则降级或追问 |
| `supportingEvidence` | 增强本结论的证据条件及其作用说明 | 不把同一照片重复视角当多份独立证据 |
| `opposingEvidence` | 能反驳、减弱或排除本结论的证据条件 | 必须参与归约，不能只展示支持项 |
| `conflictPolicy` | 支持与反驳并存、多个原因并存或来源冲突时如何降级、并列或待判定 | 不静默选置信度最高的候选 |
| `uncertaintyPolicy` | 何时可说“较可能/可能/待确认”，何时禁止“确诊”；不足时应补问什么 | 与结果确定性档位和证据门一致 |
| `severityCriteria` | 植株受损范围和程度的分级依据；与处理紧急程度分离 | 基于可观察事实，不从病名直接推出 |
| `urgencyPolicy` | 何种证据触发“立即处理/近期处理/观察复查”；给出理由 | 高风险情形须人工审核；结果按本次证据计算 |
| `isolationPolicy` | 何种证据建议隔离、明确不需要隔离或仍待确认；给出理由 | 不能把“未看见虫”自动等同“无需隔离” |
| `differentialOutcomeCodes` | 容易混淆、应对照排查的其他已发布 Outcome 代码 | 只作鉴别候选；本次结果仍由证据筛选 |
| `followUpCriteria` | 复查时间条件、观察指标与恶化/停止条件 | 由已审核知识给出范围；实际提醒由 `care` 处理 |
| `sourceClaimRefs` | 支持或反驳该结论的已审核园艺来源主张引用 | 引用定位、适用性、许可、核验时间均有效 |
| `reviewState` | 草稿、审核、驳回、撤回等治理状态；仅已发布条目可供诊断 | CMS 审核不等于发布准入 |
| `releaseRef` | 不可变诊断知识发布包的版本和 SHA-256 引用 | 与原因、Action、映射、题包兼容；历史结果锁版本 |

`urgencyPolicy`、`isolationPolicy` 是受审**判定条件**，不是所有案例共用的静态“低/否”。`sourceClaimRefs` 是内部可追溯引用，不能直接成为公开响应中的内部 ID。Outcome 不储存“立即处理/后续养护/预防/注意事项”的操作正文；这些属于 Action，并须经结论—行动映射检查禁忌。

## 已审核 Action 条目与映射字段

一隅结果页把行动分为“立即处理、后续养护、预防建议、注意事项”。青花植可借鉴这个展示分区，但一条行动须先是可独立审核、可撤回的知识条目，再根据本次结论和证据决定是否展示。以下仍是 P1 待冻结的**语义字段**，不代表已经建表或批准图中具体做法。

| 字段 | 中文含义与约束 | 来源与校验 |
|---|---|---|
| `actionCode` | 稳定行动代码；内容修订保留历史版本，改变行动目的或安全边界时另立代码 | 发布域唯一；历史结果可回放 |
| `displayCategory` | 展示分区：立即处理、后续养护、预防或注意事项 | 只是展示分类，不决定是否适用或能否执行 |
| `titleZh`、`purposeZh` | 中文行动名称与目的；说明为什么建议检查或操作 | 必须有对应的已审核结论或安全的待判定路径 |
| `stepsZh` | 用户可执行的步骤；需要药剂、剪切、用量或时间时不得写含糊指令 | 逐步骤核验来源、目标植物和本地适用性；无依据则不发布 |
| `applicabilityConditions` | 行动自身适用的植物、部位、环境和证据条件；可关联哪些结论由单独的结论—行动映射决定 | 不能把一条通用图文动作套给全部黄叶、萎蔫或虫害 |
| `contraindications`、`stopConditions` | 禁忌、暂停条件和需升级处理的信号 | 与适用条件同等参与筛选；命中时不得推荐 |
| `riskLevel`、`safetyNotesZh` | 行动风险等级及用户可见的安全提醒 | 涉及药剂、毒性、儿童/宠物、食用或不可逆修剪时必须经人工安全审核 |
| `sequence`、`followUpCriteria` | 执行顺序、复查观察点及有依据的时间条件 | 不得仅因竞品截图给出固定天数、温度、湿度或剂量 |
| `sourceClaimRefs` | 分别支持该行动、限制条件和禁忌的已审核来源主张 | 需定位到具体资料位置；不能只给整个结果挂一篇文章 |
| `reviewState`、`releaseRef` | 审核状态与不可变发布包版本 | 只允许读取已发布且与当前 Outcome 兼容的版本 |

结论—行动映射另有稳定代码、Outcome 与 Action 版本引用、命中条件、禁忌优先级、来源主张及发布版本；它不是简单的关联表。一次结果中的每条 `recommendedActions[]` 还须记录“本次为何命中”、已通过的适用/禁忌/风险检查和对应的公开来源。图中的剪叶、剪口施用粉剂、停肥两周、固定温湿度等属于**待独立核验的具体处置主张**，不能因截图出现就自动成为青花植的 Action 或默认值。

## 本次诊断结果与公开呈现字段

一隅截图的信息密度可以参考，但青花植必须把用户植物证据、判断边界和来源说清楚。下表描述公开 DTO 的**语义**；内部证据 ID、原图路径、模型原文、提示词和数据库主键不得外露。

| 字段 | 中文展示 | 生成边界 |
|---|---|---|
| `titleZh`、`summaryZh` | 结论标题与一句话摘要 | 来自已发布 Outcome 的受审文案，结合本次证据有界表达 |
| `problemType`、`causeCategory` | 问题类型与园艺原因方向 | 由已发布分类投影；症状入口另列，不伪装成原因 |
| `certaintyLevel`、`certaintyReasonZh` | “较可能/可能/待确认”及为什么 | 由证据门与冲突规则归约；MVP 不展示模型自评 `75%` 等未校准百分比 |
| `severityLevel`、`urgencyLevel`、`urgencyReasonZh` | 受损程度、处理紧急程度及依据 | 严重程度与紧急性分开；不能因文案听起来严重就自动判“紧急” |
| `isolationDecision`、`isolationReasonZh` | 需要隔离 / 不需要 / 尚不能判断，以及原因 | 依照已发布隔离条件和本次证据；证据不足不填“否” |
| `evidenceFindings[]` | 本次识别依据 | 每项有观察、部位、来源类型、采集/有效时间、支持或反驳方向；不得把推断写成观察事实。叶片受损面积等百分比，只有测量方法、分母定义和验证依据明确时才可输出，否则改用定性描述 |
| `missingEvidence[]` | 尚缺什么、为什么要补问或补拍 | 只列会改变判断的关键信息，避免机械加题 |
| `alternativeOutcomes[]` | 其他可能及如何区分 | 只引用已发布候选；逐项说明支持点、反驳点和待验证点，不并列伪确诊 |
| `recommendedActions[]` | 立即处理、后续养护、预防、注意事项 | 仅从已发布 Action 与映射选取；逐项保留适用范围、风险门、具体来源关联、安全提示、目的、顺序、禁忌和复查条件；高风险处置依据不足时不展示。用户确认前不是事实/计划 |
| `followUp` | 复查时间条件、观察点和恶化触发条件 | 没有可靠时间依据时不编造固定天数；提醒须经用户确认 |
| `publicSources[]` | 判断依据与资料来源 | 仅展示可公开的机构/标题、更新时间、合法链接和本次适用理由；无许可时展示已审核来源类型与审阅说明 |
| `knowledgeReleaseRef` | 本次使用的诊断知识版本 | 供审计/回放；对用户只展示有意义的版本说明，不暴露内部主键或哈希细节 |

长期结果还需在服务端关联 `user_id + user_plant_id`，临时结果关联本次案例；公开 DTO 不返回内部归属键。封面图片、植物档案和环境事实分别由已有授权资产/上下文提供，不复制成 Outcome 主数据。

## 仅内部使用的结果回放记录

公开呈现不能替代审计记录。一次诊断的服务端持久化记录还须锁定：题包和原因目录版本、实际命中的 `outcomeCode` 与内容版本、备选 Outcome 及其被排除/待确认理由、逐项选中的 `actionCode` 与结论—行动映射版本、各项来源主张及其 release 引用、输入证据快照与模型/规则版本，以及整个兼容发布包的 SHA-256。记录本次风险门、禁忌门、隔离门和紧急程度门的判定结果，才能按原版本回放“当时为什么给出或没有给出某条建议”。这些字段只在本域受控 Repository 与审计读取中使用，不直接进入公开响应；P1 须冻结其具体类型、保留期与脱敏边界。

## 与截图分区的明确映射

| 截图中的信息 | 青花植承接位置 | 必须纠正的风险 |
|---|---|---|
| 问题类型、主要证据 | Outcome 分类 + 本次 `evidenceFindings[]` | 问题类型来自原因分类；证据应来自具体植物，不是通用说明 |
| “约 75%”置信度 | `certaintyLevel` + 证据理由 | 未校准模型百分比不能伪装为统计概率 |
| 紧急程度、是否隔离 | Outcome 判定策略 + 本次决策与理由 | “低/否”须经本次证据支持，不能是模型默认值 |
| 识别依据、其他可能 | 证据账本 + `alternativeOutcomes[]` | 同时呈现支持、反驳和仍需核对的点 |
| 立即处理、后续养护、预防、注意事项 | Action 库 + 结论—行动映射 | 不把自由生成的操作清单塞进 Outcome，更不把建议直接写成养护事实 |

P1 完成条件：字段枚举、必填/可空、中文注释、来源引用、公开脱敏、Schema/DTO、DDL/CMS 映射与独立 Expected 一起冻结；P4 再用黄叶、萎蔫、虫害的真实案例验证结果是否既充分又安全。截图不能代替园艺真相或测试 Expected。
