# 任务描述
## 背景
青花植已基本完成黄叶模式问诊，并沉淀出基于：
*   植物属级养护数据
*   用户浇水频率
*   和风天气时光机过去 10 天温湿度
*   温湿度叠加浇水算法
*   可视化浇水行为诊断组件的水分行为判断能力。
下一步准备开发 **枯萎 / 发蔫** 问诊方向。
* * *
## 核心原则
### 1\. 不做 ranking
本任务不得引入：
*   权重排序
*   置信度排序
*   主因排序
*   最可能原因排序
*   特异性分数
*   复杂规则引擎
### 2\. route 命中即产出 outcome
每个题包答案都可以独立触发一个或多个可行动 outcomes。
最终结果是 outcome 集合，不是唯一诊断。
### 3\. 高危 block 只做动作冲突防呆
枯萎 / 发蔫场景中，部分动作存在明显冲突。
例如：

```plain
补足浇水
vs
停浇查根


```

因此需要一个极简 block 机制：

```scss
普通 route：只产出 outcome
高危 route：产出 outcome，并 block 冲突 action


```

这不是 ranking，只是 safety guard。

## Q1：发蔫形态
问题：

```plain
你现在看到的状态更接近哪一种？


```

选项与 outcomes：

| 选项 | outcome |
| ---| --- |
| 整株软塌下垂 | 全株水分压力：先减少折腾，配合水分组件处理 |
| 局部叶片 / 枝条发蔫 | 检查局部枝条、叶背、虫害或机械损伤 |
| 新叶嫩梢为主 | 保护嫩梢：避免强光、风口、浓肥 |
| 叶片干脆、卷曲、焦边 | 干枯组织处理：后续可修剪，不等待原叶恢复 |
| 不确定 | 不产出 outcome |

## Q2：发蔫节律与点位环境
问题：

```plain
发蔫通常在什么情况下更明显？


```

选项与 outcomes：

| 选项 | outcome |
| ---| --- |
| 白天明显，晚上 / 早晨缓解 | 降低蒸腾压力 |
| 靠近强光窗边、西晒、高温玻璃后 | 移离强光热源 |
| 空调、暖气、风扇直吹 | 移出直吹区，保留温和通风 |
| 全天都蔫 | 持续发蔫：结合水分组件和高危信号处理 |
| 不确定 | 不产出 outcome |

## Q3：近期应激操作
问题：

```plain
最近 7 天有没有发生以下情况？


```

选项与 outcomes：

| 选项 | outcome | block |
| ---| ---| --- |
| 刚买回家、运输、搬位置 | 缓苗稳定 | 频繁搬动 |
| 刚换盆、分株、修根、换土 | 换盆后缓苗 | 立即施肥、再次换盆、暴晒 |
| 最近大量修剪 | 修剪后恢复 | 强光、风口刺激 |
| 最近施浓肥、用药、喷清洁液 | 暂停施肥用药 | 继续施肥、继续喷药 |
| 都没有 / 不确定 | 不产出 | 无 |

* * *
## Q4：高危异常征象
问题：

```plain
有没有看到以下异常？


```

选项与 outcomes：

| 选项 | outcome | block |
| ---| ---| --- |
| 茎基部发黑、发软、塌陷 | 停浇查根茎 | 补足浇水、施肥 |
| 土壤 / 根部 / 盆底有异味 | 停浇查根、检查排水 | 补足浇水、叶面喷水 |
| 叶片发黑、水渍状、软烂 | 隔离并清理软烂组织 | 叶面喷水、继续闷养 |
| 黄叶或落叶明显增加 | 检查根系压力和排水 | 视 Q0 结果处理 |
| 虫害、蛛网、白絮、斑点扩散 | 隔离并进入病虫处理 | 与浇水不互斥 |
| 都没有 / 不确定 | 不产出 | 无 |

# 必须避免的方向
不得做：

```plain
特异性分数
复杂互斥矩阵
全局 ranking
原因概率排序
主因选择器
AI 重新推断唯一诊断


```

本任务只允许：

```scss
route 命中
outcome 产出
少数高危 block
同类 outcome 合并


```

# 验收标准
## 功能验收
*   枯萎 / 发蔫问诊包含 Q0 水分行为组件 + Q1–Q4 题包。
*   每个有效答案都能独立触发 outcome。
*   最终结果支持多个 outcomes 同时输出。
*   不出现 ranking、概率排序、主因排序。
*   高危异常可 block 冲突动作。
*   命中腐烂 / 异味 / 水渍软烂时，不输出“直接增加浇水”类行动。
*   刚换盆 / 修根 route 命中时，不输出“立即施肥 / 再次换盆 / 暴晒”类行动。
*   浓肥 / 药剂 route 命中时，不输出“继续施肥 / 继续喷药”类行动。
## 代码验收
*   outcome 数据结构保持轻量，不引入复杂权重字段。
*   block 逻辑独立封装，便于测试。
*   route 配置可读，中文主名优先。
*   不改动黄叶模式既有 route 语义。
*   不引入 ranking 或评分算法。
*   单元测试覆盖 outcome 收集、去重、block、同类合并。
## 文案验收
*   结果页表达为“建议行动清单”，不是“最可能原因”。
*   高危 block 触发时，要解释为什么暂不建议执行被 block 的动作。
*   中文为主，英文仅作为辅助术语。
*   用户不需要理解 route、block 等内部概念。
