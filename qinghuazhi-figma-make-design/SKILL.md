# 青花植 Figma Make 设计 Skill

你正在为「青花植」设计或实现界面。青花植是一个面向室内植物养护的移动产品，核心价值不是把植物装饰得更漂亮，而是帮助用户看懂植物状态，并得到下一步可执行的养护动作。

本文件是自包含的单文件 Skill。除非用户在当前任务中明确指定，否则不要引入另一套品牌、另一套色板、另一种导航结构，或凭空扩展产品功能。

## 1. 优先级与工作方式

按以下顺序做判断：

1. 当前用户的明确要求。
2. 当前项目中已存在的页面、组件、图片和交互约束；如果 Make 能读取现有项目，先检查它们。
3. 本 Skill 中的青花植基线。
4. 通用的 Figma / Make 设计惯例。

如果现有项目与本文件冲突，保留当前项目已经验证过的事实，并把冲突暴露给用户，不要静默重做整套视觉。

开始设计前，先在内部确认：页面服务谁、用户现在要完成什么、最重要的一个动作是什么。先建立信息层级，再决定装饰；只有用户要求设计说明或交接文档时才把这段判断输出出来。

## 2. 品牌核心

青花植的气质是：安静、可靠、清楚、亲近自然，但不幼稚；专业、有依据、能落地，但不制造焦虑。

用这些词指导设计：

- 轻盈而有秩序
- 植物友好，但不是植物园海报
- 工具优先，而不是内容堆叠
- 给出证据，再给出建议
- 把复杂养护过程翻译成用户能执行的一步

不要把「青花植」误读为「青花瓷」：产品主视觉不是蓝白瓷器风，也不是国潮、复古园艺店或深色森林风。Logo 使用绿色，当前应用界面也以绿色为主。

## 3. 当前首页的可复用事实

首页是一个移动端工具入口。以下是当前首页实现的事实；它们是首页基线，不自动变成所有页面的硬规则：

1. 顶部是浅绿色应用导航栏（`#E8F5E9`），标题为「青花植」，标题和导航图标使用 `primary`（`#2D7A4F`）。
2. 导航栏下方是浅绿色搜索区，左侧有「AI 识别」入口，旁边是「搜索植物」输入框。
3. 首页中部是欢迎语「您好！我是青花植」和副标题「室内绿植养护神器」。
4. 中心工具区默认展示三个等宽卡片：`诊断工具`、`浇水计算器`、`植物识别`。
5. 三个工具卡片使用白色表面、圆角、很轻的边框和阴影；每张卡片上方有一个浅绿色图标容器。
6. 用户聚焦搜索时，搜索结果以轻量列表覆盖在搜索区下方，不要把首页整体推成复杂的目录页。
7. 应用的底部主导航保持白色背景、五个入口：首页、花园、诊断、小青、我的；选中态为绿色，未选中态为中性灰。

首页不是数据看板，不需要首屏大幅植物插画、轮播广告、会员促销或大量运营模块。用户打开后应该很快看到三个核心动作。

## 4. 设计 Token 基线

下面的值是当前首页的设计基线。可以为了不同屏幕做等比例调整，但不要随意改变颜色角色或视觉比例。

### 颜色

```text
primary                 #2D7A4F   深植物绿：导航文字、主要动作、选中态
primary-soft            #E8F5E9   浅植物绿：导航背景、搜索区、图标容器、轻提示背景
primary-muted           #5A7A68   次要文字、辅助说明
accent-green            #52B788   仅在需要第二层绿色时使用；不要抢主色
page                    #F8FAF9   首页冷暖中性的浅灰绿底
warm-surface            #F8F6F0   应用其他页面可用的浅暖底色
surface                 #FFFFFF   卡片、输入框、底部导航
text                    #0A0A0A   主文字
text-secondary          #5A7A68   次要文字
border                  rgba(45,122,79,0.15)
border-strong           rgba(45,122,79,0.25)
tab-inactive            #BFBFBF
status-success          需要时复用 primary，保证对比度
status-error            使用平台语义红，克制且不作为品牌主色
```

颜色规则：

- 绿色承担品牌和行动，不要让整屏变成高饱和绿色。
- 页面背景和卡片表面要有明确层次；不要使用纯黑大面积背景。
- 蓝色不能成为主色。只有当系统状态或无障碍语义确实需要时才引入。
- 纯白卡片配深色文字，确保中文阅读对比度；浅绿色文字不要放在白底上做长段落。
- 正文和重要控件文字至少达到 4.5:1 对比度，大号文字至少 3:1；颜色不能成为传达状态的唯一方式，必要时同时使用文字、图标或形状。
- `tab-inactive` 只用于弱化未选中态，不能承担唯一的可读信息；如果未选中标签需要被清楚阅读，换用更深的中性灰。
- 在实现或原型代码中用语义化 Token 管理颜色，不要在每个组件里重复散落的原始色值。
- 首页导航栏默认使用 `#E8F5E9` 背景和 `#2D7A4F` 前景色；不要为了“高级感”自动加大面积渐变、玻璃拟态或霓虹光晕。

### Typography

- 默认使用系统中文无衬线字体，优先适配平台字体；除非用户明确提供并要求使用，不引入装饰性字体。
- 建立稳定的层级：页面标题约 20–24px、正文约 14–16px、辅助信息可用 12px，但 12px 不承载主要内容或关键操作。
- 正文行高约为字号的 1.5–1.75 倍；优先自然换行，不用强制不换行或过早省略号掩盖中文内容。
- 字重用于区分层级：标题/主要标签 600 左右，正文 400，次要按钮或标签 500；不要整页都用粗体。

### 尺寸与形状

```text
mobile-baseline         375 × 812（也适配 390 × 844）
page-gutter             16px
content-max-width       345px 左右（随屏幕宽度留出安全边距）
header-nav-height       44px，加系统状态栏安全区
search-height           41px
tool-grid-gap           12px
card-radius             16px
icon-tile               64 × 64px，圆角 16px
tool-card-height        约 146px
small-radius            10–12px
```

优先使用 4px 间距节奏；页面边距以 16px 为默认；卡片间距通常为 12px 或 16px。圆角要统一，避免同一页面同时出现 6px、10px、16px、24px 等过多半径。

视觉尺寸不等于触控热区：主要操作在 iOS 至少提供 44pt、Android 至少提供 48dp 的可点击区域；相邻操作之间至少留出 8px。搜索框或图标看起来较矮时，可以通过内边距或外层热区补足，不要为了保持视觉尺寸而牺牲可操作性。

固定的顶部导航、底部导航和底部 CTA 必须尊重状态栏、刘海、手势条等安全区，并为滚动内容预留对应的上下内边距，不能遮住最后一项内容或当前正在输入的控件。

### 阴影与边框

采用非常轻的层次：白色表面 + 细的绿色透明边框 + 低强度阴影。阴影用于区分可点击表面，不用于制造漂浮的营销海报效果。

推荐基线：

```css
border: 1px solid rgba(45, 122, 79, 0.15);
box-shadow: 0 1px 1.5px rgba(0, 0, 0, 0.10), 0 1px 1px rgba(0, 0, 0, 0.10);
```

## 5. Logo 使用

用户提供的参考 Logo 是一个方形绿色底图：大字「青花植」，下方是「植物护理神器」。它是品牌资产，不是页面背景纹理。

- 如果当前任务能读取用户上传的 Logo，优先原样使用，不要重新绘制、变形、改字、换色或添加阴影。
- 保持 Logo 的方形比例和安全留白；不要把它裁成难以识别的窄条。
- Logo 适合用于启动页、欢迎页、品牌介绍、登录或空状态；首页应用导航栏默认使用简洁的「青花植」文字标题即可，不要强行把方形 Logo 塞进 44px 导航栏。
- 如果当前任务拿不到图片资产，使用文字占位并注明「使用提供的青花植 Logo」，不要生成一个看起来相似但不准确的新 Logo。
- Logo 的绿色不等于应用 UI 的 `#2D7A4F`。使用图片时保持原图；做 UI 时仍按本 Skill 的产品色板。

## 6. 页面构成规则

### 首页

默认优先生成以下结构：

```text
浅绿导航栏：青花植（背景 `#E8F5E9`，文字 `#2D7A4F`）
浅绿搜索区：AI 识别 + 搜索植物
留白后的欢迎语：您好！我是青花植
副标题：室内绿植养护神器
三列工具卡：诊断工具 / 浇水计算器 / 植物识别
底部原生导航：首页 / 花园 / 诊断 / 小青 / 我的
```

三个工具应有相同的卡片骨架和视觉权重。只通过图标和标题区分，不要让某一个卡片变成超大营销 Banner，除非用户明确要求突出它。

### 其他页面

如果用户要求扩展到诊断、浇水、植物详情或小青页面，继承首页的颜色、圆角、边框、文字层级和底部导航，但根据任务改变内容密度：

- 诊断：以“观察到的证据 → 需要补充的信息 → 可执行建议”为层级，不直接用吓人的疾病警报式视觉。
- 浇水：把关键条件、判断结果和下一步动作分层，避免让用户先读一整页说明。
- 植物详情：优先展示植物身份、当前状态、最近记录和下一步养护；不要只做植物百科长文。
- 小青：像可靠的养护助手，不要做成夸张的聊天机器人吉祥物；对话中的思考、处理中和完成态要清楚但克制。
- 空状态：用简洁植物意象和明确下一步按钮，不要只放“暂无数据”。

## 7. 图标、插画与图片

- 工具图标使用简单、可识别的线性或轻量填充图形，视觉重量一致；优先复用已有图标，不要一页混用 3D、手绘、emoji 和照片。emoji 不作为核心导航、核心工具图标或品牌标志，只能在用户明确要求的轻量提示中辅助使用。
- 图标使用 SVG 或平台矢量图标，统一图标族、笔画粗细、圆角风格和尺寸 Token；同一层级不要混用粗细差异明显的线性图标与填充图标。
- 有可见文字的装饰图标不重复制造冗余朗读；独立的图标按钮必须有可理解的无障碍名称，并暴露选中、展开、禁用等状态。
- 新增首页核心入口时，优先使用 `植物 + 工具动作` 的抽象图形，例如叶片/放大镜/水滴/检查；不要直接用复杂的 AI 大脑、机器人头像或泛化科技图标。
- 真实植物图片使用自然光、干净背景、适度留白和真实叶片纹理。避免过饱和、过度锐化、热带丛林拼贴和假 3D 植物。
- 如果没有合适图片，使用稳定的色块、图标和留白，不要生成一张与产品语气不匹配的装饰图。

## 8. 中文文案与交互调性

中文是第一语言。默认使用简体中文，按钮、标题、错误提示和空状态都先写中文；英文只用于确有必要的技术名称或品牌名称。

文案应短、具体、有帮助：

- 使用「开始检查」「查看浇水建议」「识别植物」这类明确动作。
- 使用「先看看叶片和盆土」「不确定也可以继续」这类降低压力的表达。
- 不使用「拯救你的植物」「保证治好」「智能改变一切」等夸大或制造焦虑的承诺。
- 不把用户称为“植物小白”，不责备用户过去的养护行为。
- 不把未确认的推测写成确定结论；如果信息不足，展示“还需要补充什么”。

首页基线文案可以直接复用：

```text
青花植
AI 识别
搜索植物
您好！我是青花植
室内绿植养护神器
诊断工具
浇水计算器
植物识别
```

## 9. 交互与原型要求

如果 Make 输出的是可运行原型或代码，至少让主要入口具备清晰状态：默认、按下/悬停、加载、空结果、错误和完成反馈。没有真实后端时使用明确的本地示例数据，并在界面或代码注释中标记为演示数据，不要假装已经接通 AI 或 CloudBase。

- 搜索框要有聚焦态、清空态和无结果态；搜索结果不应遮挡标题和主要动作。
- 工具卡片要有 80–150ms 内可感知的按下反馈，反馈轻而短，不要改变布局边界、造成抖动或产生夸张的缩放和弹跳；不要只依赖 hover。
- AI 识别入口要让用户知道下一步是上传或拍照，不要只写“AI Magic”。
- 诊断、浇水建议等重要结果要把“观察/依据”和“建议动作”分开呈现。
- 异步操作要立即进入可理解的处理中状态；预计等待较长时使用稳定的骨架或进度反馈，避免空白、闪烁或假装完成。提交期间防止重复点击，失败后提供就地重试或修改入口。
- 错误信息靠近出错位置，并说明原因和恢复动作；空状态要说明下一步，不要只写“暂无数据”。
- 模态框、底部抽屉和确认按钮要保留安全区，不能被底部导航或系统手势遮挡。
- 保持“一个页面一个主要任务”，每个页面只保留一个最主要 CTA；需要更多信息时用渐进式展开、底部抽屉或下一步页面。
- 如果 Make 输出 H5 或桌面交互，为键盘操作提供可见焦点状态，焦点顺序与视觉顺序一致，且焦点不能被固定导航或弹层遮住；移动端原型和小程序代码则为独立图标控件提供可理解的辅助技术名称和状态。
- 动效只服务于状态变化、层级和空间连续性；优先使用 opacity/transform，避免动画 width、height、top、left 造成重排。动效应可中断、不阻塞输入，并在 `prefers-reduced-motion` 或系统减少动态效果时降级或关闭。
- 页面以移动端优先，不产生横向滚动；响应式扩展时保持内容顺序、触控密度和可读性，不用固定宽度把内容挤出视口。
- 顶层底部导航最多保留 5 项，并同时提供图标和文字；返回路径要可预测，进入深层页面后不要无故跳回首页，也不要把底部导航和同层侧栏混成两套主导航。
- 如果输出的是网页或前端代码，为图片预留宽高或比例，非首屏图片懒加载，避免异步内容造成布局跳动；长列表或重资源只在确有需要时加载。

## 10. 响应式与实现边界

青花植当前体验优先面向手机和微信小程序。设计桌面或宽屏版本时，保留移动端的清晰层级：可以采用居中的窄应用壳、增大留白或把卡片改为两列，但不要直接变成企业后台、密集表格或三栏数据仪表盘。

如果当前项目已有 uni-app / Vue 组件、路由、图标或请求逻辑：

- 优先复用现有组件和交互，不以新框架替换现有结构。
- 优先使用平台原生的按钮、输入框、导航和返回行为，再在其上叠加品牌视觉；不要用普通容器伪装所有交互控件。
- 只改变用户明确要求改变的视觉或体验，不擅自改写后端、身份、数据模型或业务合同。
- 不把虚构的用户植物、诊断结论、会员权益或 CloudBase 数据写成真实产品事实。
- 设计稿中的状态名称、按钮文案和页面关系要能映射到真实产品，不要只追求截图好看；动态文字放大后应允许自然换行，不用截断掩盖问题。

## 11. 生成前自检

交付前逐项检查：

- 首屏是否一眼看出这是青花植，而不是泛化的植物 App？
- 是否沿用了深绿、浅绿、白卡片、浅灰绿/暖色底的关系？
- 是否把首页核心动作放在装饰和营销内容之前？
- 是否误用了蓝白青花瓷、深色森林、乡村复古或过度可爱风？
- Logo 是否原样使用或清楚标记了待替换资产？
- 中文是否自然、短、可执行，且没有被截断？
- 主要按钮、搜索、工具卡和底部导航是否有可理解的状态？
- 主要操作是否达到 44pt/48dp 触控热区，邻近操作是否至少间隔 8px？
- 正文、按钮、图标和边框是否有足够对比度；状态是否同时通过文字或图标表达？
- 固定导航、抽屉和弹窗是否避开安全区，并没有遮住滚动内容或当前焦点？
- 加载、空结果、错误、禁用、完成和减少动效状态是否都能理解和恢复？
- 按下反馈是否及时且不改变布局；动态字体变大后是否仍能阅读和操作？
- 是否避免了未经请求的新功能、新数据、新品牌元素和不必要的依赖？
- 在 375px 左右的手机宽度下，卡片、文字、底部导航和安全区是否完整可见？

如果用户要求设计说明或交接，用中文简短说明：保留了哪些青花植基线、哪些内容是演示数据、哪些资产需要用户在 Make 中替换或确认。
