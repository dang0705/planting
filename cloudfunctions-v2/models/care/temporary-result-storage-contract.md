# 临时养护结果保存与读回

归属：E04/E06 原票 `z8v0kmr973`。依据统一计划的临时案例、不可变结果、版本回放规则，以及 004 / 017 已冻结表结构。本增量是内部存储合同，不新增公开路由，不发布养护算法。

- 输入由服务端组装：已验真的游客会话或统一用户、对应临时案例、已存在的养护会话、结果引用、环境合同版本、输入清单、算法发布清单、推导集和脱敏结果。
- 两类归属严格二选一。会话与结果必须属于同一案例；引用逐字匹配。调用方负责凭证验真，存储再次检查实际数据归属。登录临时案例不伪装为游客。
- 保存仅接收 active 的 watering 会话；生成时间不早于会话创建。结果期限来自调用方已锁定策略，必须晚于生成时间，且不超过案例、养护会话及游客会话期限。本层不设置任何默认期限。
- 四个 JSON 对象先规范化复制、计算 SHA-256，再发生异步数据库操作。外部修改原对象不得改变此次写入。结果的合同、详情版本和生成时间与外层列保持一致。
- 在调用方事务内追加，重复引用明确拒绝，不覆盖旧结果；不修改案例、不创建用户植物、行为、计划或提醒。提交未知交由调用方使用原引用核对，不自动重试。
- 读回要求相同归属、active/completed 的原会话且尚未过期。重算四组摘要并核对时间及版本，损坏结果返回 invalid_record；不存在、越权及过期统一 not_found。不用当前算法重新计算历史结果。
- 仓储返回的输入、发布引用及推导只供内部回放。公开响应只能使用上游已验证的 result。仓储不把合法 SHA 当成知识发布或算法准入证明。
- 保存应用用例先锁定输入，原引用、归属和完整内容相同则读回原结果；不同内容返回冲突。新结果事务提交后再次读回，只有原样读回成功才返回 stored。提交响应丢失、并发重复及异常仅核对一次，不自动重写，也不向调用者回传数据库错误。此规则限定内部服务端结果引用，尚不替代 HTTP 的请求幂等登记。
- 当前验证使用合成输入与已明确不可用的正式出口；算法清单中没有发布的能力保持 null，推导可为空对象，不能填写伪造 release。候选数值不会因入库而转为正式建议。

验证采用真实隔离 MySQL 和既有表/触发器，不操作云端。不新增配置或依赖；独立 Expected 与经典 RED 必须先于实现，阶段收口运行全量 Vitest。
