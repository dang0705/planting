# 养护决策模型

本目录承接统一重构计划的 E04 回放与比较阶段。四个编辑源为 `light.dmn`、`pot.dmn`、`dry-cycle.dmn`、`watering.dmn`；合成总图 `care-models.dmn` 只由下列命令生成，禁止单独编辑：

```sh
python3 scripts/backend-v2/compose-care-models.py
```

使用决策模型与标记（DMN）1.3，共 15 个决策。标识、变量和输出名使用英文，展示名称及规则说明使用中文。`manifest.json` 保存源文件哈希、稳定决策标识和输入类型。当前状态是 **未行为验收的模型草案**，没有接入生产规则执行。

## 模型与后端实现的对应关系

| 编辑源与责任 | 已实现的后端路径 | 仍缺少的实现或验收 |
| --- | --- | --- |
| `light.dmn`：输入准入、校准资格、光照结果 | `src/care/application/replay-published-mvp-light-day.ts` 将活动玻璃策略读取、双通道传播、光合光子通量密度（PPFD）与日光积分（DLI）串通；底层 `replay-indoor-natural-light.ts` 与 `replay-indoor-ppfd-day.ts` 分别承担传播和时间积分 | 完整光照策略发布、模型准入与运行代码同场景一致性、现场校准及正式 HTTP 路径尚未验收；当前日回放保持离线候选语义 |
| `pot.dmn`：实际内盆、几何、排水安全和保水准入 | `src/care/cultivation/evaluate-pot-safety.ts` 实现三值安全判断；`derive-measured-pot.ts` 计算实测圆台容器体积 | 容器体积不等于基质体积或持水量；保水策略、保水倍率及完整模型一致性尚未验收 |
| `dry-cycle.dmn`：历史循环资格、残差与个体校准 | `src/care/application/replay-completed-dry-cycle.ts` 核验循环证据并计算观察减未校准预测的区间残差 | 资格不等于已产生校准倍率；当前实现明确返回 `personalCalibration: null`，完整模型一致性尚未验收 |
| `watering.dmn`：盆土安全门、可用进度、检查窗口与行动 | 依赖上述光照、盆器和历史循环结果；当前模型规则保留为待执行验证的草案 | 基线选择、环境需求、个体倍率、干燥进度与最终浇水用例尚未完整实现和验收；不能用上游回放替代浇水闭环 |

物理计算作为外部计算输入交给 TypeScript，不虚构友好表达式语言（FEEL）函数。输入快照、发布版本和类型校验由后端负责。模型中的 `calculated_light`、`calculated_retention` 和 `calculated_personal_calibration` 需要各自的明确接线；表中存在同类计算不表示已经实现整个 DMN 决策。

### 光照输入与 MVP 边界

直射与散射共享室内传播框架，分别保留计算通道，传播后才合并。当前路径已有 SunCalc 太阳方向、窗面直射与可达性、有限窗孔散射传播、显式遮挡、玻璃和窗帘损失，以及明确参考平面上的 PPFD 与当地日期积分。原始小时均值按前一时段归一化；缺失与有效零值分别处理，缺段不输出完整全天 DLI。

MVP 只收集单层／双层玻璃分类，使用受控策略中的近似透射率。候选值单层 0.83、双层 0.70 的来源与适用范围见 `light-parameter-evidence-review.md`；候选比较不等于真实生产发布。缺策略或未知层数不补默认值，光谱换算仍须显式提供。

**保留已落地的专业参数、接口、计算与证据，MVP 暂不启用这些专业能力，也不要求前端收集复杂参数。精确光谱和现场校准不作为所有 MVP 能力的统一准入条件。** 后端估算保留来源、版本和覆盖范围，不宣称现场测量精度。

旧 NOAA 近似及其他实验回放保留各自合同和适用范围，不能与当前 SunCalc 路径混为同一算法版本。

### 跨模型关系与安全边界

合成器将浇水模型的光照、盆器和个体校准输入连接到上游决策，其余外部输入保持显式。合成检查包含局部引用、标识唯一、无循环依赖及表格列数。历史反馈发生在不同计算轮次之间。

互斥分区使用 `UNIQUE`；盆土安全门和最终行动使用按顺序命中的 `FIRST`。可靠湿土优先暂停浇水；预测超窗只要求检查。缺实际浇水起点不补零进度，未批准参数不填猜测数值。模型和离线回放都不写事实、计划或提醒。

## 验收边界

| 验证项 | 当前证据与限制 |
| --- | --- |
| XML 与生成结构 | 已有 OMG DMN 1.3 Schema 验证证据；合成器可确定性生成四源合一的 15 个决策，检查引用与依赖；这些检查不执行 FEEL |
| 后端计算 | 各叶节点和组合用例已有独立 Expected；真实 MySQL 策略读取与当地日回放有单独测试；具体结果见执行记录引用的证据，不将这些测试计为 DMN 引擎验证 |
| 专用结构校验 | 尚未执行 `dmnlint`；新增工具需要仓库规定的依赖批准 |
| 决策规则执行 | 尚未在明确版本的 Camunda 兼容执行环境中验证 FEEL、命中策略、空值、覆盖与冲突 |
| 可视化编辑 | 尚未完成 Camunda Desktop Modeler 打开、保存及重新打开的验证 |
| 双侧一致性 | 尚未完成同一组独立场景在后端与 DMN 中的结果比对，当前不得据此发布规则 |

修改 DMN 不会自动改变线上行为。正式生效前必须同步独立 Expected、对应 TypeScript 行为及发布版本，并记录模型哈希和双侧一致性证据。结构有效、引擎行为正确、HTTP 与数据库闭环分别验收。
