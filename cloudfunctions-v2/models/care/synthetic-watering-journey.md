# E04 同盆浇水模拟回放

本样本由后台自行建立，服务于 E04 养护业务推进。E05 诊断题包暂缓。样本不是实测标定，也不写入用户植物、浇水事实、计划或提醒。

## 样本来源与条件

V1 SQL已只读核验，查询及结果见 `v1-watering-sample-audit.json`。主库有1条植物、17条顾问建议，没有实际浇水事件或盆土视觉记录；开发库有54条植物、31条临时盆土视觉记录、3条提醒。31条视觉记录全部未关联植物，3条提醒虽带用户记录的浇水日期，却无同盆盆土证据。因此这些记录不构成连续干湿循环，不作为正式标定真值。

模拟盆器借用开发库一条无身份字段的外形：盆口20厘米、盆底10厘米、盆高15厘米。圆台几何容积为875π，即约2748.89毫升。原记录不证明这些尺寸是实际内盆内尺寸，也不证明排水通畅；在模拟场景中将这两项作为明确假设，原始资格不足的场景仍返回缺证据。V1材料标签不转换为持水量或已知配方。

后台控制条件如下：

| 条件 | 模拟设定及含义 |
| --- | --- |
| 观察时刻 | 2026-10-08 00:00 UTC；这是固定回放时钟，不代表真实采集时间 |
| 最近浇水日期／水量 | 均未知；不补今天或零 |
| 植物基线 | 固定为6～8等效干燥单位，仅用于该数学样本 |
| 当前状态 | 假设经合格映射得出还剩2～4干燥单位；真实表土标签不能直接得出此值 |
| 环境需求 | 区间1～2；加速场景改为2～4。它是控制变量，不是由光照或VPD线性推导的生产系数 |
| 保水与个体校准 | 对照均为1；保水增强场景为2。这些数值只属于模拟条件 |
| 水量分支 | 独立假设有效基质1800～2400毫升、当前体积含水率8%～10%、目标20%～30%；不由盆容积或材料名称猜出 |
| 策略／证据资格 | 回放中的已确认标志用于隔离验证既有分支，不构成真实发布收据；输出正式准入始终为false |

## 独立预期

同一基线下，以“剩余单位 ÷ 速度”及分段积分手算预期：

| 场景 | 算法应给出的结果 |
| --- | --- |
| 未知浇水史，从当前观察开始 | 1～4天后进入目标检查窗口；历史进度仍未知 |
| 半天后环境需求加大，第1天重新计算 | 已消耗1.5～3单位，剩余0～2.5单位；从此刻到最初观察后2.25天之间检查 |
| 保水能力变为对照的2倍 | 速度减半，窗口变为2～8天后；不修改植物基线 |
| 预计最早时间已到，但可靠根区证据仍湿 | 暂停浇水，撤回冲突的当前日期；保留原预测及证据 |
| 可靠根区证据已达目标干燥状态 | 当前可检查并通过模拟安全判断；独立净补水缺口180～528毫升，实际施水量仍未知 |

水量手算：下限1800×(0.20−0.10)=180毫升，上限2400×(0.30−0.08)=528毫升。该差值描述恢复目标含水状态所缺的水，未包含实际施水过程中供水方式、排出或滞留的影响，不能直接作为倒水量。

## 回放与验收边界

输入与独立预期存于 `fixtures/synthetic-watering-journey.json`，正式Vitest用例为 `test/care/watering/synthetic-watering-journey.spec.ts`。它调用现有盆型派生与 `replayWateringTiming`，经过观察剩余量、连续时间积分、盆土安全门、水量缺口和当地日期表达；没有替换这些数值计算。实际回放制品为 `synthetic-watering-journey-results.json`，包含输入文件SHA-256、每场景不可变快照与输出；独立Expected仍只保留在输入夹具，不能用生成结果倒写Expected。

本回放证明明确输入下业务链路的计算与安全行为，不能证明普通盆栽参数已校准、室外到室内气候已准入、光照／VPD联合响应已完成，或真实HTTP已验收。未经核验的观察映射、未知内盆或缺供排水依据仍保留缺失结果。专业字段留在后台，MVP不增加用户输入。

后续E04沿同一可回放样本替换已核验的上游数据，逐项比较光照、室内气候、基质与根区输入的影响；不把整组模拟值直接发布为默认配置。E06再验收正式策略读取、用户确认及实际行为写入。
