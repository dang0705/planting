# 长期养护环境输入快照持久化

归属 E04 原票 `z8v0kmr973`，依据 `care-environment-foundation/v2` 第三节与 `004_care_diagnosis.sql` 的快照表、不可变触发器。复用现有 mysql2 连接和调用方事务，不新增运行参数、迁移或启动 DDL。

Repository 仅接受经上游认证解析的统一用户引用和实际长期用户植物引用。写入通过参数化 `INSERT ... SELECT` 联合核验归属；无匹配植物拒绝写入。读取同样联合筛选用户、植物和快照，不存在与不归属均返回空。数据库内部键不进入读回结果，平台身份不参与业务外键。

输入清单使用规范 JSON 计算 SHA-256，读回时重新计算并核对，合法外形的摘要不能替代完整性验证。数据库唯一约束分别拒绝重复引用、同一归属的重复清单；此 Repository 的重复提交规则为明确拒绝，而不是 UPDATE、UPSERT 或复写。新事实必须提交新清单和新快照。事务提交与结果未知对账由已有事务设施及调用用例负责，本层不自行重试。

只提供追加及读取，无更新、删除接口。数据库触发器必须拒绝任何 UPDATE，包括写回原值。时间与版本符合现有 DDL：非负整数毫秒、证据窗口有序、生成时刻不早于证据结束、有效期晚于生成。有效期由调用方已经锁定的策略提供，本层不设置默认新鲜度；过期快照仍允许受控历史读回，不表示可以生成新建议。

本层不验证调用方所称事实真实性、输入清单各领域 Schema、配置快照或算法发布的准入。正式入口仍须完成相应核验，不能将本地夹具的配置引用当作已发布策略。Ephemeral 不进入此表，另按原合同内联保存临时结果。

验证采用 `unit_real_data`：实际 Repository、mysql2、隔离 MySQL 8.0.43，按指定 DDL 创建快照表及触发器，父表仅为归属夹具。覆盖写入与读回、原输入的盆器回放、重复与跨用户拒绝、新事实追加、修改拒绝、非法值及坏摘要。未证明 CloudBase HTTP、正式登录、全量迁移、配置发布或派生结果表持久化。
