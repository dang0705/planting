# 昵称与盆器测量事实持久化合同

所属票据：`z8v0kmr9mj`；执行步骤：E03。内部Repository合同，不是公开HTTP请求。

调用方必须提供显式事务、已验证统一用户引用、用户植物引用、旧聚合版本、至少一项昵称或完整的`measured-pot-profile/v1`事实、已锁定档案完整度策略版本及服务端时间。省略字段保留原事实。昵称最多80个Unicode码点，允许空字符串清除；该上限来自现有SQL列容量，不新增运营配置。策略版本不能从客户端或默认值获取。

同一事务按统一用户与植物联合锁定聚合；只有active用户的active或archived植物可编辑档案，deleting/deleted或跨用户统一不存在。旧聚合版本不匹配或版本容量用尽拒绝，不写档案。更新不改变植物引用、身份或生命周期。

首次保存创建一条档案，盆器JSON只记录明确提供的`measuredPot`；没有测量时保存空对象，不伪造全null事实。未提供昵称时沿用SQL空昵称初值。再次保存仅替换明确提供的字段，保留原JSON中基质、材质、专业参数与其他已有字段。不得截断昵称，不把SQL通配符或JSON内容拼入语句。

聚合与档案版本各自递增，但外层编辑使用聚合版本。首次档案完整时间保持为空；本子结构不足以证明完整档案，不产生奖励、outbox、事实或计划。已有首次完成时间、创建时间和完整度版本保留，不通过局部编辑重新评定或清空。

保存后在同一事务读回昵称、存在时的严格测量事实及新聚合版本，不公开数据库主键或平台主体。写入或读回不确定时抛出受控内部错误，由事务驱动整体回滚；Repository不自行提交、重试或执行DDL。

应用层已通过共享幂等占位与完成收据、提交未知新连接只读核对的验证；正式HTTP仍须冻结完整公开响应并完成身份/策略接线，不能直接公开内部读回。

真实SQL验收使用隔离MySQL与现有用户植物/档案表，覆盖新建、局部更新保留、跨用户、旧版本、并发和回滚。用户认证、完整档案Schema、HTTP和正式策略发布分别验收。
