# 待审诊断候选只读合同

本合同属于 E02/E05 原票 `z8v0kmr971` 的 CMS 审核准备环节。依据统一重构计划的原样候选、精确引用、审核发布分离要求及 `009_diagnosis_knowledge.sql`，不新增可配置变量。

审核读取必须明确给出 `candidateRef` 与 `contentSha256`，不能读取或替换为“最新”候选。只接受 `submitted` 状态，重新核验完整 JSON Schema、正文摘要及行外版本字段；草稿、驳回、已审核或不存在均不作为待审候选。提交时间必须存在、合法且不早于创建时间。

同一短事务先读取候选，再复核明确题包发布引用、来源主张修订、许可和适用性。数据库候选和异步读取期间的查询输入均不能被调用方修改。结果为递归冻结的完整待审快照、原引用、完整摘要和提交时间，不是批准凭证。

无法提供记录、完整正文、正确摘要或有效依赖时返回明确不可用。数据库读取异常交由事务驱动回滚并传播；不吞异常伪造不存在，不盲重试。

这是内部用例，不登记公共 HTTP 路由，不接管理员鉴权，不发布审核协议。正式 CMS 管理员、协议和知识内容仍须独立准入。读取不写候选、审核、发布、指针、奖励、诊断结果或养护事实。

验收分别标记隔离连接测试和真实 MySQL 读回；结构制品不等于园艺知识、人工审核或 CMS 端到端验收。
