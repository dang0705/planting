# 复用题包的养护时间线证据

归属 E05 `z8v0kmr974`。题目不变：只有服务端快照声明 `uiVariant: care_behavior_timeline` 且用户选择 `care_behavior_timeline`，才允许消费附带时间线。成员、空气复合证据和时间线全部通过，才可进入后续提交持久化；零题虫害继续交直判用例，不成为空答案提交。

沿用 V1 发送的 `careBehaviorTimeline`，兼容 `care_behavior_timeline`；两者同时出现须规范化后一致。时间线内部保留 V1 snake_case 和 camelCase 两种字段：参考日期、三类事件列表、施肥时间段，以及后端历史形态的 dailyRecords。别名同时出现时不得冲突。这里只验证明确的证据，不引入业务倍率、默认量、缓存或保留期。

参考日期、每条事件及每日记录的日期必须是有效的 YYYY-MM-DD，不读取系统当前日期补齐。事件不可晚于参考日期；不静默裁掉过期记录，不猜测十天之外是否无行为。缺列表表示未提供；空事件列表不能证明没有浇水。至少一条实际事件、明确的每日行为记录，或已知施肥时间段才构成非空证据。

浇水事件保留用户申报的 amount 和数值 amountMl；缺失或 null 是未知，不转换为零或默认量。数值必须有限且非负，字符串数值拒绝。watered 为 false 的事件不得被转为 true；明确未浇水只能以每日记录中的布尔值保存。施肥、光照事件保留明确字段，不根据默认量生成事件。同类型同日事件相同可去重，冲突则拒绝。每日记录保留明确的浇水/施肥布尔值；不把天气数据当作养护行为。

规范化输出只含证据字段，不带客户端事件ID、计划ID、来源声明、摘要、模型推断或原始内部字段。用户的行为申报不构成 care 已完成事实，不重置 DryProgress，不触发奖励。未知答案不能附加时间线；客户端额外题包不授权。时间线全部通过不代表来源发布、会话归属、HTTP、事务或实际事实已验收。

来源：用户批准复用V1题包；V1客户端 sidecar 发送结构与日期事件字段；整体计划关于实际行为、不可变快照、缺证据不得伪造以及服务端成员授权的规则。V1日期、用量的便利默认值明确不进入后端证据语义。
