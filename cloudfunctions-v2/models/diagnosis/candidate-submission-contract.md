# 诊断候选提交合同

归属 E02/E05 原票 `z8v0kmr971`，承接待审候选只读合同。正式 CMS 管理员和交换协议尚未准入；本增量仅为受控内部用例，不开放 HTTP 写接口，不执行云端迁移。

输入明确包含新修订 `candidateRef` 和完整 `candidate`。完整候选先按受控 Schema 校验并复制冻结，计算规范 JSON SHA-256，再读取数据库；候选不能提供 Schema 或配置。不存在新阈值或默认审核协议。

首次提交在短事务中复核明确题包、来源主张修订、许可与适用性，然后把完整正文、原引用、版本及摘要写入 `diagnosis_knowledge_candidates`，状态为 `submitted`。创建和提交时间使用同一个受控服务器时刻。数据库引用和 `(bundle_code, revision_no)` 唯一约束保证不会覆盖另一修订。

重复提交作用域为候选引用及完整正文：同引用、同正文返回原始提交时间；同引用不同正文或另一个引用占用同包同修订号返回冲突。重放是历史提交收据，不能把已驳回或已审核候选重新改成待审，不授予当前来源、审核或发布资格。已有草稿且没有原提交时间时，不当作本用例的提交成功。

正常提交必须读回完整正文、行外版本、摘要及原时间才返回成功。异常事务回滚；并发唯一键或死锁失败后仅用新连接只读核对胜出提交，禁止自动重跑写入。提交结果未知同样只读对账，未找到收据就返回 `unknown_commit`，不伪报失败或成功。

这里只新增候选，不写审核、不可变发布、活动指针、贡献奖励、最终诊断或养护事实。结构制品、替身来源及本地数据库测试分别说明，不能代替 CMS 或园艺内容验收。
