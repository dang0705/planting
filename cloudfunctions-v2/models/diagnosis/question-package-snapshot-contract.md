# 服务端题包快照持久化

归属 E05 原票 `z8v0kmr974`。首版继续复用 V1 黄叶、萎蔫和虫害内容，不建立新题库。题包来源准入与服务端实际选出的题目分开：运行用例先核验精确发布版本，再锁定该次题目、选项和完整元数据。

快照合同 `diagnosis-question-package-snapshot/v1` 保存 `questionPackageReleaseRef`、`mode`、`questionCount` 和 `packageQuestions`。完整纯 JSON 内容使用既有规范化 SHA-256；题目和选项数组保持顺序，不删去复合题、风险及跳过说明。快照一旦建立，题目、选项、所属模式和发布引用不可替换。这里没有新增可调整参数：合同版本为代码常量，归属与不可变性为硬规则，不配置默认发布引用、时限或重试策略。

顺序迁移 `019_diagnosis_question_package_snapshots.sql` 为长期和临时会话增加 `question_package_snapshot_json` 与 `question_package_snapshot_sha256`。两列均空表示历史缺快照；两列同时存在才构成可验证记录。新插入必须有快照，更新不可替换快照、题包引用或症状模式；长期会话的用户与植物归属、临时会话的案例归属同样不可改写；会话状态仍可独立推进。数据库只保护结构与不可变性，内容摘要须由 Repository 读回重新计算。

长期会话 Repository 只通过统一用户公开引用与用户植物公开引用解析内部归属；创建只允许有效用户的有效植物，读取同时核对用户与植物。客户端提供内部主键无效；题包来源与审核准入由受控上层负责。重复诊断引用由唯一键拒绝；业务请求的重复提交仍需应用层接既有幂等设施，不把重复插入误报为成功。

迁移不改变旧字段、不覆盖历史数据；旧记录两列保持空，不能用于题包作答。验收需核对旧行数量、NULL配对、真实数据库约束、摘要和归属读回。只在隔离库验证，不执行生产迁移。回退以保留原快照数据、回退应用读取路径并停止新建会话为前提；没有数据处置证据不得删除列。历史不可重放会话明确返回缺少快照，不能从今天的题包补出昨天的内容。

本增量不验收 CMS 发布、完整迁移链、临时案例全部归属路径、题包回答写入或 HTTP 诊断，也不生成结论、行动或养护事实。
