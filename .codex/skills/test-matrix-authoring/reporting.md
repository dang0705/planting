# 排雷与合格率交付（编写推进）

仅当本轮被授权「写/改测试或产品」时必出完整排雷。纯审查、纯只运行 → 报告结果或缺口即可。  
分类口径与何时必出，见 `SKILL.md` §1 / §5 摘要。

先表后合格率。禁止把 B/C 写成已修复的排雷。

| 分类 | 含义 | 算「已排雷」 |
| :--- | :--- | :--- |
| **A** | 测试暴露的**产品**缺陷（无论本轮是否改了代码） | 仅当状态为已修 |
| **B** | 逻辑本正确，测试钉死 | 否 |
| **C** | 仅 harness / mock / 选择器 | 否 |

发现与修复分开：表 1 列全 A；**N = 本轮已修条数**。未授权修改的真实缺陷仍进表 1，标「未修」，不得因未改代码而删掉或改标 B。

## 合格率（不得替代表 1）

| :--- | :--- |

反例：源码未改的预期行为 → B；mock 让用例可跑 → C；只报绿屏、适用维缺失、把 skip 当通过 → 不合格。

## 闸门 0 声明（编写推进必出）

从 [product-safety.md](product-safety.md) 三选一抄进交付：`本轮产品改动：无` / `仅修 A 或授权改产品（会红的用例名）` / `违规，已回滚`。

同轮改了产品文件时，表 1 或证明范围须再写闸门 5 三问的答案（用户路径、会变红的用例名、删 helper 测是否仍能抓回归）。答不出 = 本轮未完成。

## 测试真实性记录（编写/修改必出）

每个本轮声称完成的关键对象至少写一行；可合并同一测试边界，但不能只写套件摘要：

| 对象 / 用例 | Break：会抓住的错误改动 | Expected：独立来源 | Real path：经过 / 替换 | Mutation：会变红的突变 |
| :--- | :--- | :--- | :--- | :--- |
| `Foo` / `…` | 错分支、错参数或缺少副作用 | 契约、规格、手算 fixture | 真实 SUT；替换的边界 | 代表性突变 + 用例名 |

不能指出会失败的代表性突变 → 状态写 `缺口`，不得用通过数或覆盖率替代。详见 [test-integrity.md](test-integrity.md)。
