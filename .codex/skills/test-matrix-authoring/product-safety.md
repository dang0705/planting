# 矩阵不得制造源码 bug

`SKILL.md` §3.8 的细则。只在本轮会改产品、peel/抽 helper、冲覆盖、或对象适用 C7/U7 时读。  
不管浅测硬度（那是 [validity.md](validity.md)）。本文件只拦：**测法把产品改坏，测试还绿。**

原则：测试只证明产品。覆盖率、可测性、peel 都不是改接线的许可。

**与 TDD：** 闸门 2 = 真 TDD 的 RED→GREEN（先宿主红，再改产品）。丢掉的是「先改接线 / peel 再补绿、只测 helper 却自称 TDD」。Characterization ≠ TDD。

## 何时停工

命中任一条 → 本轮未完成；产品 diff 须回滚到闸门满足为止。

| # | 闸门 | 停工条件 |
| :--- | :--- | :--- |
| 0 | 声明 | 交付没有且仅有一句：`本轮产品改动：无` / `仅修 A 或授权改产品（<会红的用例名>）` / `违规，已回滚` |
| 1 | 冻结 | 补测/冲覆盖/characterization 改了控制流，且未走「授权改产品」+ 闸门 2 |
| 2 | 先红 | 先改了产品（含 peel 后改调用点）再补测；没有「旧代码上红」的宿主用例 |
| 3 | 宿主证明 | 改了同步/deps/被宿主调用的谓词，但没有「用户动作 → 下游业务结果」；或删掉谓词单测后抓不住这次回归 |
| 4 | 迁就 | 为让测试好写/去 flake/涨覆盖而改产品语义，或用错误谓词断言回写产品 |
| 5 | 三问 | 产品有改动，但答不出：改了哪条用户路径、哪条测试会因此变红、闸门 3 自检是否为是 |

## 闸门 1 — 默认冻结的控制流

禁止改（除非闸门 0 = 授权改产品 / 修 A，且已先红）：

- 同步 effect / watch 的 deps 或方向（谁覆盖谁）
- 事件到 query 参数 / store / mutate 的路径
- 默认值、短路、错误吞或抛
- 产品导出上的测试专用 props / 强制入口（强制调用只许留在测试替身）

**peel 并把宿主改为调用新 helper = 改控制流。** 过不了闸门 2+3 → 不抽文件，只测原宿主。

允许：只加测试；只改 harness；修表 1 的 A（先红）。

## 闸门 2 — 先红后改（TDD）

凡授权改产品（修 bug 或改行为）：改之前必须已有宿主用例，在**当前**产品上失败，失败原因 = 目标用户可观察结果未达成。然后改产品至绿。这就是 RED→GREEN。

禁止：先改 deps / 先抽 helper 改调用点 → 再补测。  
Characterization 只许钉现行行为，当时不得改产品；要改 = 另一步，仍先红。

## 闸门 3 — 同 diff 宿主证明

改了谓词、deps、或「源 → 本地」同步时，同 diff 必须有一条用例同时满足：

1. 驱动用户动作（点选、改 draft、打开后再动受控源），不是只调纯函数
2. 断言下游结果（query 参数、confirm payload、层开关、mutate/store 是否发生）
3. 若源立刻覆盖用户态（或 `source !== local` + local 在 deps），该用例红
4. 删光谓词/`*.helpers` 单测后，这条仍能独立抓住本次回归

替身可替换外壳，但动作必须打到宿主 handler。mock 掉宿主同步或整页编排 hook 来避开接线 = 本闸失败。

## 闸门 4 — 矩阵任务测不了接线时停（≠ 禁止 TDD）

任务是补测/冲覆盖、且**还没有**会红的宿主用例时：不许为了「先让行可测」去改产品。只许加厚 harness、标 `浅 / 缺口`、换层/E2E。

若任务是授权改产品：先把「测不了」变成「能红」（加厚 harness / 换层），再走闸门 2。不能红 = 还不能改，不是放弃 TDD。

不许：改产品迁就谓词测、用错误语义钉 Happy 再改接线去迎合、吞错/删异步/放宽条件刷绿、快照错误语义再逼产品对齐。

**迁就反例（已发生）：** 为让导航图探针 / L2 断言 `goToRoute(...)` 变绿，拆掉结算页已共享的 PIPL（宿主 `Text` + 既有 CMS 打开路径），改成 `Text` 内嵌 `span` + 另一套路由键。测试绿、真机协议链消失或不可点 = 闸门 4 失败，须回滚产品接线，改测以对齐真实路径，而不是改控件迁就断言。

**谁执行：** 过本文件闸门、写测、改产品均服从 `SKILL.md` §3.10。非具名子代理不得代过闸门；主代理漏读本文件仍算违规。

## C7 / U7

适用条件与独立 Reverse 要求见 `SKILL.md` §2.1。只测 helper = 该维缺失。合同若是「源全量覆盖」，覆盖表写明依据，否则按「用户态不被源毁掉」测。
