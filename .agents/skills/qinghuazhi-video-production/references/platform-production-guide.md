# 多平台获客视频策划规范

## 责任边界

本文件负责定义抖音、小红书、微信视频号的获客短视频策划规则，包括：

- 获客命题；
- 前 3 秒观看理由；
- Scene / Shot 信息组织；
- 产品出现方式；
- 信息密度；
- CTA；
- 跨平台共同母版；
- 平台原生感。

工作流状态、审批门禁、Plan Schema、Provider 与 Render 规则由专用合同 Reference 定义。

当字段枚举或执行规则存在冲突时，以：

- `plan-contract.md`
- `performance-model.md`
- `workflow.md`

为准。


## 目标

把用户的一句话创意转成适合抖音、小红书、微信视频号的获客短视频 Plan。

Plan 必须同时做到：

- 前段立即给出观看理由；
- Scene 是叙事阶段，Shot 是 Scene 内具体镜头；
- 内容像平台原生内容，不像传统 TVC 硬广；
- 青花植功能展示使用真实小程序录屏；
- 不夸大诊断、浇水或养护能力；
- 跨平台时优先生成三端都成立的共同母版。

## Plan 方法

### 1. 先确定获客命题

先明确：

1. 用户正在遭遇什么具体问题？
2. 视频希望改变用户哪一个认知？
3. 青花植在哪个时刻作为解决方案出现最自然？

优先从真实痛点进入，例如：

- 到底该不该浇水？
- 黄叶到底是缺水还是浇多了？
- 固定几天浇一次为什么还是出问题？

不要先介绍品牌、Logo 或功能列表。

### 2. 前 3 秒

跨平台默认把前 3 秒视为必须交付“观看理由”的窗口。

可用：

- 痛点：`今天到底该不该浇？`
- 反常识：`黄叶不一定是缺水。`
- 结果预告：`我终于不用每天猜什么时候浇水了。`
- 视觉冲突：人物拿水壶犹豫 + 植物近景。

禁止：

- Logo 片头；
- 空镜头铺垫；
- “大家好今天给大家介绍……”；
- 后文不兑现的标题党。

### 3. Scene / Shot

对 20~35 秒获客视频，默认优先：

- 2~4 个 Scene；
- 5~8 个 Shot。

Scene = 一个叙事阶段。  
Shot = Scene 内的具体镜头，是最小制作单元。

同一个“问题展开” Scene 可以连续包含：

```text
人物焦虑
→ 植物特写
→ 查看盆土
```

不要默认一个 Shot 建一个 Scene。

### 4. 产品出现方式

青花植应作为“解决当前问题的工具”自然出现：

```text
问题
→ 不确定性 / 误区
→ 青花植真实功能
→ 用户获得更明确的下一步
```

小程序 UI：

- 只能规划为 `app_capture`；
- 必须使用真实录屏；
- 不允许 AI 生成虚假按钮、虚假结果页或不存在的能力。

### 5. 信息密度

一个 Shot 只承担一个主要信息点。

如果一句话同时让用户理解多个概念，优先拆 Shot 或缩短文案。

人物对白：

- 短句；
- 口语化；
- 少广告腔；
- 不为凑时长重复信息。

### 6. 字幕

同一份 `speech.text` 同时作为：

```text
TTS
+
字幕
```

不能再写第二套字幕。

### 7. CTA

默认一个 CTA。

优先：

- 先看下浇水建议，再决定要不要浇。
- 植物出问题时，先别急着凭感觉处理。

避免连续要求关注、点赞、评论、私信、下载。

### 8. 跨平台共同母版

同时面向三端时：

- 9:16 竖屏；
- 前 3 秒直接进入问题 / 价值；
- 真人/植物场景生活化；
- 有语音就有字幕；
- 产品能力以真实录屏证明；
- CTA 轻量；
- 封面作为发布素材独立处理，不把静态封面硬塞进视频开头；
- 不使用只在单个平台成立的强导流话术。

## 青花植专属护栏

- 植物症状素材只展示素材中真实存在的症状。
- Wan 只负责动态化，不负责创造诊断证据。
- 不把“建议”说成“确定诊断”。
- 不使用“100%”“一定”“绝对不会”等无证据承诺。
- 人物对话 Shot 一次只出现一个说话主体；双人对话使用 A Shot → B Shot。
- AI 人物只能作为剧情角色，不能包装成真实专家或真实用户证言。

## 证据纪律

参考文件按证据级别使用：

- A：官方平台 / 官方广告与创作者资料；
- B：可信行业研究；
- Project：青花植当前经过实测的生产约束。

广告投放经验不能无条件升级为自然流量算法硬规则。


## Shot 表现模型

每个 Shot 必须输出：

- `speech.mode`：`dialogue / voiceover / none`
- `rhythm`：`紧凑 / 自然 / 舒缓`
- `emotion`：`平静 / 放松 / 安心 / 高兴 / 兴奋 / 自信 / 疑惑 / 怀疑 / 犹豫 / 惊讶 / 担心 / 心烦 / 烦躁 / 不耐烦 / 无奈 / 失望 / 挫败 / 伤心 / 焦虑 / 紧张 / 害怕 / 慌张 / 愤怒 / 暴躁`
- `stance`：`默认 / 安抚 / 鼓励 / 共情`
- `expression`：`默认 / 低声 / 耳语 / 喊叫 / 玩笑 / 秘密感`
- `transitionAfter`：`硬切 / 轻柔`

### 使用纪律

- `emotion` 选择最具体、最符合台词语义的状态。
- `stance` 表示对听众的姿态，不是情绪；大多数 Shot 使用 `默认`。
- `expression` 表示表达方式，不是情绪；大多数 Shot 使用 `默认`。
- 不要输出 Azure Style、Voice、styleDegree、temperature 或 Wan 参数。
- Performance Mapper 会将统一语义分别翻译成 Azure Dragon HD Flash 和 Wan 的控制语言。
- 不要为了让视频“更有戏”而无理由提高情绪强度或频繁切换状态。
