# 测试真实性与突变检查

写/改测试进入**测试实现与真实性验证阶段**时读本文件；添加 mock/helper、走 Fast Path、写 Reverse/高风险接线、做 Mutation/执行反写时必须读对应细则。纯只运行不读；纯审查仅在测试真实性存疑时读。用语见 [jargons.md](jargons.md)。它补充 `validity.md` 的“有没有测到适用维”，只回答一个问题：**这条测试能否抓住真实的错误改动，而不是只为覆盖率变绿。**

## 0. 落盘前一条用例一张卡（KPI / 未点名文件时必填）

写测试体前先能口头答出，交付时并入真实性表。答不出 → 不落盘。

```text
对象 / 层 / §2.1 维：
形态：Happy | Edge | Reverse（互斥；为何不是另外两种）
Expected 来源：DTO/接口 | 设计硬锁或样例 | 需求 | 允许形状的 fact | common scene | characterization（须列缺源）
Break / Expected / Real path / Mutation：同 §5
若只为盖某行、无独立职责 → 不写，计入安全上限
若 Expected 从 SUT/源码抄 → 不落盘为 TDD
产品是否要改：否（默认）。硬锁已红 → 停，走 product-safety 解冻，禁止为 % 改
```

覆盖率、文件路径、`describe("edge")` 标签都不是形态。形态只看主断言。

## 1. 先写出会抓什么错

写测试体前，先在用例旁或工作记录中回答：

```text
若产品发生什么错误改动，这条测试会失败？
这是产品缺陷，还是有意改变的决策？
```

合格的答案是用户可观察的错误：错分支、错参数、缺少状态/副作用、边界未防御、错误处理错误。以下答案不合格：

- “源码这一行变了”
- “helper 返回值不再是这个值”，但没有说明它破坏了哪个消费者结果
- 只有常量或文案变了才失败
- 期望值由 SUT 或 SUT 的 helper 计算出来

对于 page、hook、编排和接线，测试落在第一个消费者可见结果：query 参数、渲染状态、confirm payload、导航、mutate/store 副作用。纯函数才直接断言其输出。

## 2. 期望值必须独立

期望值来自外部真相源（DTO/接口文档/制品/live、经分档的设计、需求规格、允许形状的跨会话 fact）与 common scene；不要复用被测函数、同一 mapper、共享 builder 来生成 `expected`。细则：[truth-sources.md](truth-sources.md)。

```ts
// 不合格：两边使用同一个实现，永远可能相等
const expected = buildQuery(input);
expect(buildQuery(input)).toEqual(expected);

// 合格：期望值是独立、可审计的结果
expect(buildQuery(input)).toEqual({ filterId: 302, pageSize: 20 });
```

如果期望值无法独立写出，先回到产品合同或选择更高层的行为边界，不要用实现镜像冒充证明。

**设计稿 / 原型作来源时：** 先分「结构功能硬锁 / 内容样例 / 待确认」，再落断言。禁止把单帧运营文案或图层占位名升成死合同，再用红测逼改产品。步骤与分层用法见 [design-expected.md](design-expected.md)。

## 3. 替身只替边界，不替被测行为

添加替身前先列出真实依赖的副作用，保留本条测试依赖的部分，只替换慢、外部、不可控的边界。

- 不断言 mock 自己存在；断言真实 SUT 的结果。
- mock 内部模块时，必须写清证明范围；不能把被 mock 掉的编排、接线或副作用算作已测。
- mock 响应应保留真实合同所需的完整结构，不能只填断言恰好读取的字段。
- mock setup 明显大于测试行为、或替身吞掉了确认/取消/错误通道时，停止加 mock，改用更高层的集成测试或加厚 harness。

允许为 L2 隔离网络、query 工厂或重量级子树，但宿主风险仍须经过真实 handler，并断言下游业务结果；否则只能报告为壳门闸，不得写成整条业务链已覆盖。

## 4. 交付前做突变检查

对每个本轮声称已覆盖的对象，选适用的真实突变，确认至少一条测试会失败：

- 错参数、错 id、错 payload 字段
- 删除状态更新、导航、mutate、toast 或其他必要副作用
- 反转条件或走错 success/error/empty 分支
- 去掉默认值、空值/非法值防御
- 把源值错误地覆盖本地态，或把用户选择错误地覆盖回旧值

### 4.1 心智突变 vs 执行反写

| 本轮新写 / 加厚的形态 | 突变检查最低要求 |
| :--- | :--- |
| **Reverse**、半截受控链（C6 类）、高风险接线（确认/取消/pending/禁用不得副作用） | **至少 1 条执行反写**（见下） |
| Happy、纯 Edge 展示（空态/loading/文案门闸） | **心智突变**即可；答案不确定时仍应升级为执行反写 |

**执行反写（抽检义务，四步缺一不可）：**

1. **临时改坏**：隔离工作区只改产品一行（或等价一处语义）；禁止顺手改测试期望来「配合」红。
2. **必须先红**：跑预期会咬合的用例；未红 → 测偏弱，标缺口，不得宣称完成（先还原再改测）。
3. **写回（硬义务）**：探针改动必须**完整还原**到反写前内容；禁止只还原一半、禁止把探针留作「顺手修产品」、禁止与其它产品 diff 混留。
4. **写回后须再绿**：同一相关套件再跑通过。

**写回验收（交付前强制）：** 被探针触碰的产品文件相对反写前无残留 diff（可用 `git diff -- <paths>` / 工作树对照）；若工作区本就有无关脏文件，须点名列出探针 path，并证明这些 path 已无探针语义。缺写回证据 = **未完成 / 违规**，与缺红证据同等。

交付至少写：红证据（用例名 + 临时改动语义）+ 写回证据（已还原的 path + 写回后再绿的套件结果）。勿留探针 diff 进提交。

**词表隔离（禁止混读）：**

| 词 | 是什么 | 不是什么 |
| :--- | :--- | :--- |
| **执行反写** | 临时探针：证明已有测试能变红 | 不是 Reverse 形态；不是交付态产品改动 |
| **Reverse case** | 正式用例：产品保持正确，断言坏结果不得发生 | 不是故意把产品改坏 |
| **产品改动 RED 证据** | `product-safety` 闸门 2：Classic 用旧行为上的宿主 RED；Fast Path 用受控回退/Mutation 的反事实 RED | 执行反写可提供 Fast Path 证据，但探针本身不是产品改动授权 |

无法指出会失败的用例，或命中上表却未做执行反写 / 反写未红 / **未完整写回** / 写回后未再绿 → 该风险标记为 **缺口**，不得用绿屏或覆盖率宣称完成。

这不是要求为每条测试安装 mutation-testing 工具，也不是要求对无职责的代码发明突变；突变必须对应对象真实职责和本轮风险。执行反写的唯一合法终态是**产品与反写前一致**；探针不得进入提交，也不构成改产品授权。

## 5. 交付记录

编写/修改模式的证明范围中至少保留以下四项：

```text
Break：这条测试会抓住的错误改动
Expected：独立期望值的来源
Real path：经过的产品代码；替换的边界
Mutation：会使测试变红的代表性突变及用例名
         （命中 §4.1 执行反写档时：红证据 = 用例名 + 临时改动语义；
          写回证据 = 已还原 path + 写回后再绿的套件结果；缺任一 = 未完成）
```

`product-safety.md` 的 RED 证据与宿主证明仍是产品改动的硬闸门。普通突变检查不能绕过闸门 2；只有满足 `SKILL.md` §0 Fast Path 的受控回退/Mutation 才可作为其反事实 RED 证据。钉现状 ≠ TDD。写回未完成 = 等同未授权产品改动残留。
