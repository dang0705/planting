# 矩阵 skill 停工卡 dry-run

**何时读：** 需要对撞已知翻车/验证停工卡，或任务、diff、审查对象出现以下**可观察事故信号**时读：peel、改接线、共享控件、源状态↔用户本地态同步/deps、宿主真实路径/控件改动、coverage 驱动的产品改动。仅有普通产品改动或正常无冲突 TDD 不预读。

证明范围：按 `SKILL.md` §3.3 核对 **GE + G0–G5**；可一次性自检，命中任一停点即停。用语见 [jargons.md](jargons.md)。  
本文件证明的是「若执行停工卡，该步不得落盘」；不是运行时强制。新翻车必须补进 §1，并写清第一停点。

用法：复述当时动作 → 只许用停工卡问答 → 写下第一停点与不得落盘的文件。不得事后改写当时动机。

## 1. 已发生翻车（必须全拦）

### K0 从实现生成 Expected 自称 TDD

- **当时：** 读 mapper/页面源码写出 `expected = mapX(dto)` 或把现行渲染当合同，覆盖率上涨，交付写成合同验收 / TDD。
- **核对：** GE：Expected 来自 SUT → **停**（不得落盘为 TDD）。即便误过：无独立硬锁 Expected / 无可审计 RED 证据却宣称修了产品语义 → G3/G4。
- **第一停点：** GE。合法路径：按 DTO/文档/设计硬锁/需求手写 Expected；缺源则标明 characterization。
- **裁定：** 拦住。

### K1 共享打开路径 → 测试友好 DOM + 另一套导航 API

- **当时：** 审查认为某内容/协议链应走统一导航内核。用户批准「改导航图并补 L1 图探针」。主代理同时改页面共享打开控件：拆掉既有共享链，改成测试更好点的内嵌节点 + 另一套路由，测试断言统一导航 API。
- **逐步：** G0 否（本步不是冲覆盖）。G1 是产品（页面打开控件、共享打开路径）。G2：用户点名的是导航图与图探针，**未点名**改打开控件或导航 API → **停**。即便误过 G2：G3 当时真机链可见，红的是「未调用统一导航 API / 图缺边」，不是用户可观察失败 → 停。G4 是为断言/编译边变绿 → 停。G5 回写共享打开约定 → 停。
- **第一停点：** G2。允许只改边声明 + 探针测试。禁止改打开控件。
- **裁定：** 拦住。

### K2 测试命名把「追加选中」回写成「独占」

- **当时：** 为可测抽出谓词，按测试名把宿主改成「每次只留一项」；产品真实语义是保留已选项并追加新项。
- **逐步：** G1 产品（宿主 / helpers）。G2 无用户点名「改成独占」→ **停**。G3 无「当前产品上用户可观察失败已红」→ 停。G4 谓词/命名回写产品 → 停。
- **第一停点：** G2。只许 characterization 钉现行「保留 + 追加」。
- **裁定：** 拦住。

### K3 恒等 peel 凑水位

- **当时：** 为覆盖抽出与宿主条件表达式恒等的 helper，并改宿主调用点。
- **逐步：** G0：仅有水位目标不停；本步要 peel 改宿主 → G0 停（peel 凑水位）。即便把 peel 说成「抽取」：G1 产品，G2 未点名抽 helper → 停。G4 为 % 变绿 → 停。
- **第一停点：** G0（用 peel 追水位）或 G2。合法路径：挂合格 L2 测原条件，或把该壳计入安全上限。
- **裁定：** 拦住。

### K4 无红改受控层同步方向

- **当时：** 先改弹层/受控源如何覆盖本地开关，再补同值 rerender 的 Reverse。
- **逐步：** G1 产品。G2 未点名改同步方向 → **停**。G3 无「旧代码上红」→ 停。闸门 2 同样失败。
- **第一停点：** G2。
- **裁定：** 拦住。

### K5 无真实响应依据的字段写入 mapper

- **当时：** 把未在真实响应出现的字段写入 mapper / model，测试用强制断言或手造 DTO 冒充 Happy。
- **逐步：** G1 产品 DTO。G2 未点名该字段 → **停**。G5 未在真实响应出现 → 停。硬规则 3 禁止 L3 Happy 臆造契约。
- **第一停点：** G2 / G5（并列，先走到谁停谁）。
- **裁定：** 拦住。

### K6 并行非具名子代理冲覆盖

- **当时：** `Task` × `generalPurpose` / `explore`，目标 90–95% Lines，peel 与 L2 并行落盘。
- **逐步：** 水位目标本身合法。G0 命中的是**非具名子代理**（及 peel）→ **停**。主代理按 §3.12 合法路径继续追 X%。
- **第一停点：** G0（手段，不是目标）。
- **裁定：** 拦住。

### K7 Characterization peel 自称 TDD

- **当时：** 先抽 helpers 改调用点，再补绿，交付写成 TDD。
- **核对：** G1 peel = 产品。该案只有 Characterization，没有独立硬锁 Expected，因此不满足 G3 Classic/Fast Path RED 证据 → **停**。
- **第一停点：** G3。只许测原宿主；要改产品必须先取得独立硬锁 Expected，并满足闸门 2 RED 证据。
- **裁定：** 拦住。

### K8 图探针倒逼产品打开路径

- **当时：** L1 边表写入「某页 → 某内容边」，再改打开控件去实现这条边（与 K1 同 diff）。
- **逐步：** 补边本身若用户点名导航图 → G2 仅对边声明通过。下一步改打开控件：G2 未点名控件 → **停**。G4 边与产品对不上时应改探针/标缺口，或另走「真机链打不开」的先红，不得改控件迁就边。
- **第一停点：** 改打开控件时 G2。
- **裁定：** 拦住。

**§1 结论：** K0–K8 均在落盘前有第一停点；无「只能事后回滚」的漏项。

### 1.1 前提改为「冲到 X%」时（目标合法）

用户原话只有「冲到 90% / 95% Lines」，**没有**点名改某个产品文件。G0 对「仅有水位目标」= 不停，进入合法路径。下面每步仍是当时那种翻车动作，看第一停点还在不在。

| 动作（为凑 X%） | G0 | 若误过 G0 | 第一停点 | 拦住？ |
| :--- | :--- | :--- | :--- | :--- |
| 用 SUT/mapper 生成 expected 自称 TDD（K0） | GE → 停 | — | **GE** | 是 |
| 开 `Task`/`generalPurpose` 并行写测或 peel（K6） | 非具名子代理 → 停 | — | **G0 手段** | 是 |
| 抽恒等 helper 并改宿主（K3） | peel 追水位 → 停 | G2 未点名抽 helper；G4 为 % | **G0** | 是 |
| 先 peel 再自称 TDD（K7） | peel → 停 | G3 无先红 | **G0** | 是 |
| 为可测把「追加」改成「独占」（K2） | 改接线 → 停 | G2 未点名改语义；G4 | **G0** | 是 |
| 无红改受控层同步（K4） | 改接线 → 停 | G2 / G3 | **G0** | 是 |
| 臆造字段进 DTO 好测（K5） | 改接线 → 停 | G2 / G5 | **G0** | 是 |
| 拆共享打开路径、换测试友好 DOM 好吃行（K1/K8） | 改接线 → 停 | G2 未点名控件；G4/G5 | **G0** | 是 |
| 空挂载 page smoke 刷行 | 空挂载 → 停 | — | **G0** | 是 |
| 改 exclude / 分母假装到了 X% | 不改产品，但 §3.12 禁止 | — | **§3.12** | 是（交付假完成） |
| 合法补测后停在 81%，交付写成「已到 90%」 | 手段合法 | — | **§3.12 / 硬规则 13** | 是（谎报） |
| 合法补测后停在 81%，交安全上限 + miss 分类 | 不停 | — | 无停（诚实完成） | 不该拦 |

「冲到 X%」**不**等于点名 peel / 改某页宿主 / 改打开控件 / 改 DTO。G2 在误过 G0 时仍是第二闸。

**1.1 结论：** 放开水位目标后，已发生翻车仍全拦；拦的是凑数手段和谎报，不是目标。唯一放行的是合法路径或诚实安全上限。

机器闸门：改产品源码会 `permission: ask`，测试文件 allow。无 paths 配置。见 `SKILL.md` §3.4 与仓库闸门脚本自测。确认卡不能替代 G3 的 RED 证据。脚本/产品路径以仓库为准，需要时读 `hosts/` 下本轮已命中的适配。

## 3. 自测口令（下一轮写测前默念）

0. Expected 来自 DTO/接口、设计硬锁、需求、允许 fact 或 common scene 了吗？从 SUT/源码抄 → GE 停，不是 TDD。
1. 有没有用 `Task` / peel / 改接线追 Lines%？有 → 停。仅有水位目标 → 按合法路径做（每条仍过 GE）。
2. 要不要改非测试文件？无独立硬锁 Expected 或无法满足 G3 RED 证据，且 KPI/补测未点名 → 停。确认卡也不能为 % 改。解冻须有明确 Scope，并满足 Classic 或 Fast Path 闸门 2。
3. 硬锁 Expected 是否已在当前产品上红？没有 → 只加测，禁止先改产品。
4. 是不是为了绿一条断言/%/可测性？是 → 改测不改产品。
5. 交付有没有 §0 来源 + 闸门 0 + Mutation？把钉现状写成 TDD → 未完成。
