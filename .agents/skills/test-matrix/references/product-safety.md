# 矩阵不得制造源码 bug

`SKILL.md` §3.9 / §3.3 的细则。用语见 [jargons.md](jargons.md)。**准备写产品源码前必读**；或命中 peel、改接线、共享控件、产品授权/冻结判断时读。coverage/KPI 只有在开始考虑产品改动、授权/冻结、peel 或改接线时才触发；纯 coverage 运行/静态审查不预读。若 G1=测试/harness 且本轮不改产品，不预读本文件。  
不管浅测硬度（那是 [validity.md](validity.md)）。本文件只拦：**测法把产品改坏，测试还绿。**

原则：测试只证明产品。覆盖率、可测性、peel、图探针、统一导航键都不是改接线的许可。执行路径可以自由，但产品改动必须有独立 Expected、明确 Scope 与可审计 RED/GREEN 证据；新增 / 修正产品可观察行为还必须满足 `SKILL.md` §0 的 executable Test First 底线。

## 授权范围（两层，不可混）

**产品改动**以原话点名的文件与行为为准，不得用审查建议或 KPI 扩权。  
**测试落盘**在任务是补测 / 冲 X% 且未点名文件时，由 [validity.md](validity.md) §2 选择协议选出对象，**不**要求用户先点名每个文件。选择协议 ≠ 改产品许可。

| 用户原话 | 允许（测试） | 允许（产品） | 不允许 |
| :--- | :--- | :--- | :--- |
| 补测 / 加深矩阵 / 审查 | 加测试、加 harness、标缺口；Expected 须独立 | 无（除非独立硬锁 Expected 与产品冲突 → 确认卡 + 闸门 2 修 A） | 从源码发明 Expected；无 RED 证据改接线 |
| 改导航图 / 补 L1 图探针 | 探针测试 | 只改原话点名的边声明 | 改页面打开控件、共享打开路径、换导航 API |
| 修表 1 的 A | 宿主证明 | 确认卡 + §2 RED 证据后只改**该条** | 顺手「对齐」未被点名的实现 |
| 冲覆盖 / 冲到 X%（可无文件名） | 按 §2 选对象补有效测；交不出则交安全上限 | 仅当有独立 Expected + 确认卡 + §2 RED 证据时改产品 | peel / 空挂载 / 无 Expected 改接线 / 仅为 % 申请确认卡 / 非具名子代理 |
| 确认卡同意某次写入 | — | **仅该文件本次**写入；须已满足闸门 2 | 把 KPI 或「允许补测」读成整仓授权 |

审查结论「这里应该走统一导航内核 / 应该改成另一种选择语义」在未满足闸门 2 之前，**不是**授权改产品。测试命名不得反写业务语义。

**执行反写探针**（[test-integrity.md](test-integrity.md) §4.1）允许临时改产品一行以证明用例会红。**写回是硬闸门**：须完整还原探针 path、写回后再绿，并在交付交写回证据。未写回 / 半写回 / 把探针混进其它产品 diff = **产品安全违规**（等同未授权改动残留）。执行反写本身不构成产品改动授权；在 §0 Fast Path 中，它可作为闸门 2 的反事实 RED 证据。

### 未点名文件时如何不改坏源码

KPI /「补测」**没有**点名产品文件时：**禁止无独立 Expected / 无 RED 证据改产品**；允许 Classic 先红，也允许满足 `SKILL.md` §0 的 Fast Path。

1. **Expected 必须先独立固定。** miss 行再高，也不是改 deps / peel / 换打开 API 的理由，也不是从源码发明 Expected 的理由。没有独立硬锁 Expected 时只动测试与 harness；有独立 Expected 时产品改动仍须闸门 2。
2. **产品改动必须有 RED 证据。** Classic：硬锁独立 Expected 在当前产品上失败 = 表 1 的 A，确认卡后改至绿。Fast Path：Expected 已先固定且范围清楚；新增 / 修正行为时须先落至少一条表达该 Expected 的代表性 executable test（新写或已有），再可一次完成其余测试 / 产品实现；交付前必须受控回退/Mutation 使目标用例 RED，再完整恢复 GREEN。源码先改后补代表性测试不满足 Fast Path；须先回滚对应产品改动再重新进入，或按非 TDD 补测如实报告。
3. **禁止为水位去点确认卡。** 确认卡通知的是「修这条独立 Expected 所定义的产品冲突」，不是凑 X%。闸门 4 命中（仅为断言 / % / 可测性变绿，且没有可审计 RED 证据路径）→ 连卡都不要弹，改测或交安全上限。
4. **钉现状不是默认。** Expected 必须来自外部真相源；采源可与测试侦察同轮完成。仅缺源时才允许标明的 characterization，当时不得改产品。测绿不得改产品去迎合测；硬锁 Expected 测红不得先改 Expected 吞 A。冲突处理见步骤 2。
5. **机器闸门**（`SKILL.md` §3.4）拦 Write/StrReplace；拦不住 Shell/人手。代理不得用 Shell 改产品来躲确认卡。

独立 Expected 与产品冲突时必须按闸门 2 提供 RED/GREEN 证据（Classic 或 Fast Path），不得把「未点名 / 补测」理解成禁止修 A，也不得把钉现状绿屏当成 TDD 完成。没有独立 Expected 或最终拿不出 RED 证据的产品改动必须回滚。

## 何时停工

命中任一条 → 本轮未完成；产品 diff 须回滚到闸门满足为止。

| # | 闸门 | 停工条件 |
| :--- | :--- | :--- |
| 0 | 声明 | 交付没有且仅有一句：`本轮产品改动：无` / `仅修 A 或授权改产品（<会红的用例名>）` / `违规，已回滚` |
| 1 | 冻结 | 无独立硬锁 Expected 却改了控制流，或未走「授权改产品」+ 闸门 2 |
| 2 | RED 证据 | 产品改动既没有 Classic 的旧代码 RED，也没有 Fast Path 的受控回退/Mutation RED；或反事实 RED 失败仍保留产品改动 |
| 3 | 宿主证明 | 改了同步/deps/被宿主调用的谓词，但没有「用户动作 → 下游业务结果」；或删掉谓词单测后抓不住这次回归 |
| 4 | 迁就 | 为让测试好写/去 flake/涨覆盖而改产品语义，或用错误谓词断言回写产品 |
| 5 | 三问 | 产品有改动，但答不出：改了哪条用户路径、哪条测试会因此变红、闸门 3 自检是否为是 |

## 闸门 1 — 默认冻结的控制流

禁止改（除非闸门 0 = 授权改产品 / 修 A，且满足闸门 2 RED 证据）：

- 同步 effect / watch 的 deps 或方向（谁覆盖谁）
- 事件到 query 参数 / store / mutate 的路径
- 默认值、短路、错误吞或抛
- 产品导出上的测试专用 props / 强制入口（强制调用只许留在测试替身）

**peel 并把宿主改为调用新 helper = 改控制流。** 过不了闸门 2+3 → 不抽文件，只测原宿主。

允许：只加测试；只改 harness；修表 1 的 A（满足闸门 2）。

## 闸门 2 — RED 证据（Classic / Fast Path）

凡授权改产品（修 bug 或改行为）都必须证明：独立 Expected 与错误实现能真实咬合。代理可自行选路径：

- **Classic**：改产品前已有宿主用例在当前产品上 RED，失败原因 = 目标用户可观察结果未达成；然后改至 GREEN。
- **Fast Path**：独立 Expected 已在实现前固定、Scope 清楚且已获确认卡；新增 / 修正行为时，至少一条表达该 Expected 的代表性 executable test（新写或已有）已先于对应产品行为修改落盘。满足后可一次完成其余测试 / 产品改动；交付前必须受控回退目标改动或做等价 Mutation，让宿主用例 RED；随后完整恢复并 GREEN。反事实 RED 失败 → 闸门失败，产品 diff 必须回滚或测试补强后重证。

禁止：先读实现发明 Expected，再用回退表演 RED；**先改对应产品行为、后补代表性测试，即使之后 Mutation 会红，也不满足 TDD Test First**；先 peel/改 deps 后只补一个镜像测试。Characterization 当时不得改产品。

## 闸门 3 — 同 diff 宿主证明

改了谓词、deps、或「源 → 本地」同步时，同 diff 必须有一条用例同时满足：

1. 驱动用户动作（点选、改 draft、打开后再动受控源），不是只调纯函数
2. 断言下游结果（query 参数、confirm payload、层开关、mutate/store 是否发生）
3. 若源立刻覆盖用户态（或 `source !== local` + local 在 deps），该用例红
4. 删光谓词/`*.helpers` 单测后，这条仍能独立抓住本次回归

替身可替换外壳，但动作必须打到宿主 handler。mock 掉宿主同步或整页编排 hook 来避开接线 = 本闸失败。

## 闸门 4 — 矩阵任务测不了接线时停（≠ 禁止 TDD）

任务是补测/冲覆盖、且**还没有**会红的宿主用例时：不许为了「先让行可测」去改产品。只许加厚 harness、标 `浅 / 缺口`、换层/E2E。

若任务是授权改产品：先把「测不了」变成「能被独立 Expected 验证」（加厚 harness / 换层），再走闸门 2。既不能 Classic RED、也不能 Fast Path 反事实 RED = 还不能保留产品改动。

不许：改产品迁就谓词测、用错误语义钉 Happy 再改接线去迎合、吞错/删异步/放宽条件刷绿、快照错误语义再逼产品对齐。

**迁就反例（模式）：** 为让图探针或 L2 断言「统一导航 API」变绿，拆掉页面已有的共享打开路径（宿主文本控件 + 既有内容页打开方式），改成测试更好点的 DOM 形态 + 另一套路由。测试绿、真机链消失或不可点 = 闸门 4 失败，须回滚产品接线，改测以对齐真实路径，而不是改控件迁就断言。控件专名不写在本文件。

**谁执行：** 过本文件闸门、写测、改产品均服从 `SKILL.md` §3.11。非具名子代理不得代过闸门；主代理漏读本文件仍算违规。落盘前必须能指出停工卡 GE、G0–G5 的通过理由；可一次性自检，无需表演固定顺序。对不上 [incident-dryrun.md](incident-dryrun.md) 同类案 → 停。  
机器核对：改产品源码走 Cursor 确认卡（`SKILL.md` §3.4），无 JSON 放行。未同意不得落盘。
