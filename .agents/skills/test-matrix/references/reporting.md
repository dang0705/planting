分类口径与何时必出，见 `SKILL.md` §1 / §5。用语见 [jargons.md](jargons.md)。

## 合格率（不得替代表 1）

| 命令或任务 | 结果 |
| :--- | :--- |
| … | passed / failed / skipped（skipped = 未验证） |

任务含水位时，合格率表之外另附：当前%、目标 X%、exclude、安全上限、剩余 miss 分类。数字不能替代缺口或闸门 0。未到 X% 须写清上限原因，不得把「已到 X%」写进完成结论。

反例：源码未改的预期行为 → B；mock 让用例可跑 → C；只报绿屏、适用维缺失、把 skip 当通过、缺闸门 0 或真实性表 → 不合格。

## 闸门 0 声明（编写推进必出）

从 [product-safety.md](product-safety.md) 三选一抄进交付：`本轮产品改动：无` / `仅修 A 或授权改产品（会红的用例名）` / `违规，已回滚`。  
改了产品源码时，须已经过用户确认卡同意（`SKILL.md` §3.4），且**不是**为水位/%/可测性而改。KPI 未点名文件时闸门 0 应为 `本轮产品改动：无`，除非走了已红的 A。不得用配置文件代替确认卡。

同轮改了产品文件时，表 1 或证明范围须再写闸门 5 三问的答案（用户路径、会变红的用例名、删 helper 测是否仍能抓回归）。答不出 = 本轮未完成。

| 对象 / 用例 | Break：会抓住的错误改动 | Expected：独立来源 | Real path：经过 / 替换 | Mutation：会变红的突变 |
| :--- | :--- | :--- | :--- | :--- |

不能指出会失败的代表性突变，或本轮新写 Reverse / 半截受控链 / 高风险接线却无执行反写红证据或无写回证据 → 状态写 缺口，不得用通过数或覆盖率替代。详见 [test-integrity.md](test-integrity.md) §4.1。执行反写 ≠ Reverse case；普通反写不自动获得产品改动授权，Fast Path 作为 RED 证据仍须满足 `product-safety.md` 闸门 2；未写回 = 产品安全违规。
