# 实施护栏

## 1. 安装与 easycom

`uni-ui` 推荐通过 `easycom` 使用。实现时优先检查项目是否存在：

- `uni_modules/uni-xxx`
- `uni_modules/uni-scss`
- `package.json` 中的 `@dcloudio/uni-ui`
- `pages.json` / `easycom` 配置

不要在页面中默认写：

```js
import UniBadge from '@/uni_modules/uni-badge/components/uni-badge/uni-badge.vue'
```

除非仓库已有这种手动注册规范。默认直接在 template 使用：

```vue
<uni-badge text="1" />
```

## 2. Vue3 + Vite

如果仓库是 Vue3 + Vite，通常不需要为 npm 安装的 `@dcloudio/uni-ui` 额外添加 `vue.config.js` 的 `transpileDependencies`。不要把 Vue2/Webpack 时代的配置机械带入。

## 3. 微信小程序优先风险清单

| 组件 | 风险 |
|---|---|
| `uni-file-picker` | 文件选择只支持 H5 和微信小程序；微信使用 `wx.chooseMessageFile()`；不绑定服务空间时 `autoUpload=false`。 |
| `uni-popup` | 弹出后不一定完全阻止背景滚动，必要时手动锁定滚动容器；open 建议在 mounted/onReady 后。 |
| `uni-swipe-action` | 长列表慎用 `autoClose`；不可嵌套在 `swiper` 内；微信端用了 wxs 优化但仍需真机/开发者工具验收。 |
| `uni-transition` | 小程序 rotate 动画不要写 `deg` 单位；依赖 sass。 |
| `uni-collapse` | 小程序端内容变化后可能需要 `resize()`。 |
| `uni-grid` | 列数最好不超过 5；组件内必须有内容。 |
| `uni-tooltip` | 不能遮挡原生组件；移动端不要把关键说明只放在 hover。 |

## 4. 样式策略

- 优先使用组件 props / slots 完成结构和状态。
- 颜色优先对齐 `uni-scss` 变量：`$uni-primary`, `$uni-success`, `$uni-warning`, `$uni-error`。
- Figma 中的像素值不要机械逐项照搬。先判断是组件内置间距、页面布局间距，还是设计特例。
- 如果项目使用 Tailwind / UnoCSS，只把工具类用于外层布局和局部修饰，不要粗暴覆盖组件内部结构。

## 5. 何时自定义

以下情况不要硬套 uni-ui：

- Figma 设计是强品牌化视觉，组件 props 无法表达核心样式。
- 组件交互语义不匹配，只是视觉看起来相似。
- 组件平台限制会影响主平台微信小程序的关键流程。
- 组件需要引入大量依赖，而该页面只需要一个极小静态效果。

自定义时仍要说明：

```text
该区域未使用 uni-ui：原因是 xxx；保留的官方组件替代是 yyy；后续如设计收敛可切回 zzz。
```

## 6. 验收清单

提交前检查：

- 是否已输出 Figma 区域到 uni-ui 组件映射表。
- 是否所有使用的 `uni-ui` 组件都已在项目中可解析。
- 是否遗漏 `sass`、`uni-icons`、子组件依赖。
- 是否区分了 `tag/badge`、`popup/drawer`、`calendar/datetime/dateformat`、`select/picker/checkbox/combox`。
- 微信小程序端是否重点检查文件选择、弹层滚动、滑动手势、动画。
- 是否标明需自定义的区域，而不是伪装成组件可覆盖。
