# 用 SVG（view 组件）替换 PNG 并实现气流动画

## 背景与约束
- mp-weixin 不支持 `<image>` 里的 SMIL SVG 动画，也不支持模板内联 `<svg>`。项目现有动画都是 CSS `@keyframes` 在 `<view>` 上实现（已确认）。
- 用户选择方案：**view + CSS 动画组件**（推荐方案）。
- AGENTS.md：禁 SCSS，可用 `<style scoped>` 普通 CSS；单文件接近 500 行必须拆分；不新增依赖。

## 实现方案

### 1. 新建场景子组件 `src/components/AirflowScene.vue`（~200 行）
按 Figma 450:3445/450:1509 的房间俯视图，用原生 view 元素绘制房间场景，气流部分用 CSS @keyframes 动画。

**props**：`scene`（`'window-one'` | `'window-two'` | `'fresh-air'` | `'closed'`）、`idPrefix`

**场景结构**（每个场景一个相对定位容器，比例固定）：
- 房间外框：圆角 16px，底色 `rgba(241,248,244,0.5)`
- 左墙/右墙：竖线条 `#2D7A4F` opacity 0.15
- 窗户开口（开窗卡才有）：墙上的开口区域，白色矩形 + 绿色边框
- 植物：中心位置（pot inset ~56.84%/49.5%/24.21%/49.5%，foliage inset ~46.32%/46%/36.84%/46%），用绿色圆/椭圆 view 组合
- 气流指示器：虚线/箭头，用 view + CSS 动画

**四种场景的窗户与气流差异**：
- `window-one`：仅右侧窗户开口 + 右侧气流（参考 two 的左窗）
- `window-two`：左右两侧窗户开口 + 左右双向气流
- `fresh-air`：左进右出流动动画（左侧进气流 → 贯穿房间 → 右侧出气流）
- `closed`：无窗户开口，无气流（静态）

**气流动画 CSS**（`<style scoped>` 普通 CSS）：
- `@keyframes airflow-flow`：`translateX(-30%) → translateX(30%)` 循环，模拟气流横向流动
- `@keyframes airflow-dash`：`stroke-dashoffset` 或 `background-position` 偏移，模拟虚线流动
- 新风"左进右出"：左侧气流元素从左向右流，右侧气流元素延续方向，形成贯穿效果
- 开窗气流：窗户处的虚线竖向/横向流动

### 2. 修改 `src/components/AirExchangeAssessment.vue`
- 删除 4 个 PNG import
- 用 `<AirflowScene :scene="..." :id-prefix="idPrefix" />` 替换 4 处 `<image>`
- 开窗卡：`:scene="input.windowDirectionCount === 'two_or_more' ? 'window-two' : 'window-one'"`
- 新风卡：`scene="fresh-air"`
- 关闭卡：`scene="closed"`
- 保持所有稳定 id、props、emit、selectSource/selectWindowDirection/selectWindowFrequency 逻辑不变

### 3. 删除 `src/assets/airflow/` 下的 4 个 PNG 文件
不再需要位图资产。

## 风险与注意
- view 绘制的房间场景会比 Figma 原图简化（Figma 有十几个矢量片段），但会保持核心视觉要素：房间外框、墙壁、窗户开口、植物、气流指示器，配色对齐 Figma（#2D7A4F / rgba(45,122,79,0.15) / #F1F8F4）。
- 气流动画用 CSS @keyframes，mp-weixin 原生支持，与项目现有动画模式一致。
- 单开窗参考两开窗的左窗：window-one 只渲染右墙窗户开口（即 two 的左窗镜像），不渲染左墙开口。
- 组件拆分后 AirExchangeAssessment.vue 行数会减少（移除 image 逻辑），AirflowScene.vue 作为独立场景组件约 200 行，均不超 500 行。
